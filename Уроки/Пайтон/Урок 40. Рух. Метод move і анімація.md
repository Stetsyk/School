## 2. Пояснення (8-10 хв)

### Блок 1. Фігура має ім'я

Досі ми малювали й одразу забували. Насправді кожна команда малювання **повертає** значення — номер, за яким полотно знає цю фігуру. Його називають ідентифікатором.

Щоб потім щось із фігурою робити, номер треба зберегти у змінну:

```
мяч = полотно.create_oval(50, 50, 100, 100, fill="red")
```

Тепер `мяч` — це не сама фігура, а її номер. Але користуватися ним можна саме як іменем фігури.

Це те саме `return`, яке ми вивчали на уроці 33: команда щось повернула, і ми це зберегли. Раніше нам номер був не потрібен, бо ми нічого з фігурами не робили.

> 📝 Кожна команда малювання **повертає номер фігури**. Щоб потім змінювати фігуру, номер зберігають у змінну:
>
> ```
> мяч = полотно.create_oval(50, 50, 100, 100, fill="red")
> ```

> ❓ **Що лежить у змінній `мяч` після цього рядка?**
>
> *Очікуємо:* не сама фігура, а її номер на полотні.

### Блок 2. Команда move

Тепер фігуру можна посунути.

```
полотно.move(мяч, 10, 0)
```

Три аргументи: яку фігуру рухати, на скільки **змінити x** і на скільки **змінити y**.

Головне тут — це саме зміщення, а не нові координати. `move(мяч, 10, 0)` означає «посунь на 10 пікселів праворуч», а не «постав у точку 10».

| Виклик | Куди рухається |
| --- | --- |
| `move(id, 10, 0)` | праворуч на 10 |
| `move(id, -10, 0)` | ліворуч на 10 |
| `move(id, 0, 5)` | **вниз** на 5 |
| `move(id, 0, -5)` | **вгору** на 5 |
| `move(id, 5, 5)` | праворуч і вниз навскіс |

Не забуваємо, що `y` росте вниз: щоб фігура полетіла вгору, зміщення має бути від'ємним.

Ще дві корисні команди для вже намальованої фігури: `полотно.itemconfig(мяч, fill="blue")` міняє їй колір, а `полотно.delete(мяч)` прибирає з полотна.

> 📝 **Рух фігури:** `полотно.move(номер, dx, dy)`
> Числа — це **зміщення**, а не нові координати.
> `dy` додатне рухає **вниз**, від'ємне — вгору.
> `itemconfig(номер, fill="blue")` міняє колір · `delete(номер)` прибирає фігуру.

> ❓ **Як посунути фігуру на 20 пікселів угору?**
>
> *Очікуємо:* `полотно.move(номер, 0, -20)`.

### Блок 3. Цикл анімації

Один `move` дає стрибок. Щоб вийшов рух, потрібен цикл — і в ньому ще дві речі.

```
import tkinter
import time

вікно = tkinter.Tk()
полотно = tkinter.Canvas(вікно, width=600, height=400, bg="white")
полотно.pack()

мяч = полотно.create_oval(50, 180, 100, 230, fill="red")

for i in range(100):
    полотно.move(мяч, 5, 0)
    полотно.update()
    time.sleep(0.02)

вікно.mainloop()
```

Два нові рядки в тілі циклу, і обидва обов'язкові.

**`полотно.update()`** каже вікну перемалюватися просто зараз. Без нього Python порахує всі сто кроків миттєво й покаже лише кінцевий результат — м'яч просто з'явиться праворуч.

**`time.sleep(0.02)`** робить паузу на дві сотих секунди. Без неї сто кроків промайнуть швидше, ніж око встигне помітити. Модуль `time` підключають зверху, як і будь-який інший.

Швидкість руху задають двома числами: розміром кроку в `move` і тривалістю паузи. Більший крок — швидше й ривками, менша пауза — плавніше й швидше.

> 📝 **Цикл анімації:**
>
> ```
> for i in range(100):
>     полотно.move(мяч, 5, 0)
>     полотно.update()
>     time.sleep(0.02)
> ```
>
> `update()` перемальовує вікно, `time.sleep(секунди)` робить паузу. Без них руху не буде видно.

> ❓ **Що станеться, якщо в циклі анімації забути `полотно.update()`?**
>
> *Очікуємо:* фігура просто з'явиться в кінцевій точці, руху не буде видно.

### Блок 4. Відбивання від країв

Тепер зробимо так, щоб м'яч не тікав за екран, а відбивався.

Для цього потрібні дві речі: знати, де м'яч зараз, і мати змінну напрямку.

Команда `полотно.coords(мяч)` повертає **список** із чотирьох координат фігури: `[x1, y1, x2, y2]`. Це звичайний список з уроку 24, тому працюють індекси:

```
позиція = полотно.coords(мяч)
лівий_край = позиція[0]
правий_край = позиція[2]
```

Напрямок зберігають у змінній, і при досягненні краю змінюють знак:

```
dx = 5

while True:
    полотно.move(мяч, dx, 0)
    позиція = полотно.coords(мяч)
    if позиція[2] >= 600 or позиція[0] <= 0:
        dx = -dx
    полотно.update()
    time.sleep(0.02)
```

Рядок `dx = -dx` і є відбиванням: було 5, стало −5, і м'яч поїхав назад. Наступного разу знову стане 5.

Тут узято `while True` замість `for`, бо м'яч має літати нескінченно. Зупинити таку програму можна, закривши вікно.

> 📝 **Відбивання:** напрямок зберігають у змінній `dx`, а при досягненні краю міняють знак: `dx = -dx`.
> `полотно.coords(номер)` повертає список `[x1, y1, x2, y2]` — де фігура зараз.
> Перевірка правого краю: `позиція[2] >= ширина_полотна`.

> ❓ **Що робить рядок `dx = -dx`?**
>
> *Очікуємо:* змінює напрямок руху на протилежний.

#### ✅ Відповіді до бонусів

**Бонус 1.**
```
dy = 0
while True:
    dy = dy + 0.5
    полотно.move(мяч, 0, dy)
    позиція = полотно.coords(мяч)
    if позиція[3] >= 400:
        dy = -dy * 0.8
    полотно.update()
    time.sleep(0.02)
```
Тут дві ідеї. Тяжіння — це щокрокове збільшення швидкості, а не постійна швидкість. А множення на 0.8 при відбиванні означає втрату частини енергії, тому м'яч стрибає щоразу нижче, як справжній.

**Бонус 2.** тримати м'ячі й напрямки в списках.
```
мячі = []
напрямки = []
for i in range(10):
    x = random.randint(0, 550)
    y = random.randint(0, 350)
    мячі.append(полотно.create_oval(x, y, x + 30, y + 30, fill="red"))
    напрямки.append([random.choice([-4, 4]), random.choice([-4, 4])])
```
Далі в циклі анімації перебирають усі м'ячі за індексами й рухають кожен своїм напрямком. Це поєднання анімації зі списками з уроку 26.

**Бонус 3.** Кроків `400 / 5` = **80**, часу `80 × 0.02` = **1.6 секунди**. Звідси видно, як керувати швидкістю: збільшити крок або зменшити паузу. Перше робить рух швидшим, але смикнутим, друге — плавнішим, але навантажує комп'ютер. Зазвичай паузу лишають близько 0.02, що дає приблизно 50 кадрів за секунду, і міняють саме крок.

**Бонус 4.** Поки м'яч ще перебуває за межею, умова істинна **на кожному кадрі**, і знак швидкості перевертається щоразу заново. Виходить рух на п'ять пікселів туди й одразу назад — це й видно як тремтіння. Лікують двома способами. Простіший: перевіряти ще й напрямок руху, тоді розворот стається рівно один раз.
```
if x > 500 and dx > 0:
    dx = -dx
if x < 0 and dx < 0:
    dx = -dx
```
Надійніший: після розвороту одразу повертати м'яч у межі полотна командою `coords`, щоб він фізично не лишався за краєм.

## 7. Якщо лишився час

**Скільки кадрів на секунду треба.** Кіно знімають із частотою 24 кадри на секунду — цього достатньо, щоб рух здавався плавним. Ігри роблять 60 кадрів і більше, бо там важлива швидкість реакції: чим частіше оновлюється екран, тим менше затримка між натисканням і рухом на екрані. Наша пауза 0.02 секунди дає приблизно 50 кадрів на секунду.

**Чому анімація може смикатися.** Якщо комп'ютер не встигає намалювати кадр за відведений час, рух стає нерівним. У професійних іграх це вирішують хитро: рахують, скільки часу минуло з попереднього кадру, і зсувають об'єкт саме на стільки, скільки він мав пролетіти за цей час. Тоді при просіданні швидкості рух лишається рівним, просто менш плавним.
