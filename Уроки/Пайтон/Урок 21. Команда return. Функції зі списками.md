## 2. Пояснення (12-15 хв)

### Блок 1. Команда return

`return` англійською — «повернути». Ця команда віддає результат туди, звідки функцію викликали.

Порівняємо дві версії однієї функції.

```
def вартість_друк(ціна, кількість):
    print(ціна * кількість)

def вартість(ціна, кількість):
    return ціна * кількість
```

Перша друкує. Друга повертає — і результат можна зберегти:

```
s = вартість(5, 4)
print(s)                  → 20
print(s * 2)              → 40
print(вартість(5, 4) + вартість(3, 3))    → 29
```

З першою версією так не вийде. Вона нічого не віддає, а лише виводить на екран.

> 📝 **`return`** повертає результат туди, звідки функцію викликали.
> Результат можна зберегти у змінну й використати в обчисленнях: `s = вартість(5, 4)`
> **`print` показує результат людині. `return` віддає його програмі.**

> ❓ **Яку версію функції взяти, якщо результат потрібен для подальших обчислень?**
>
> *Очікуємо:* ту, що з `return`.

### Блок 2. Найважливіша різниця

Це місце, де плутаються всі. Проговоримо його ще раз, бо різниця принципова.

| | `print` | `return` |
| --- | --- | --- |
| Куди йде результат | на екран | у програму |
| Чи можна зберегти | ні | так |
| Чи можна використати далі | ні | так |
| Хто бачить | людина | програма |

Найпоказовіший приклад:

```
def сума(a, b):
    print(a + b)

x = сума(2, 3)      → на екрані з'явиться 5
print(x)            → None
```

На екрані з'явилося `5`, тому здається, що все працює. Але у змінній `x` лежить `None` — «нічого». Функція вивела число, але нічого не повернула.

`None` — це спеціальне значення, яке Python підставляє, коли повертати нічого. Побачили `None` там, де чекали число — шукайте забутий `return`.

> 📝 **`None`** — значення «нічого». Функція без `return` повертає саме його.
> Якщо у змінній опинилось `None` замість числа — у функції забули `return`.

> ❓ **Функція друкує 5, а у змінній опинилося `None`. Що забули?**
>
> *Очікуємо:* команду `return`.

### Блок 3. return завершує функцію

Ще одна властивість: щойно виконався `return`, функція **одразу закінчується**. Усе, що написано після нього, не виконається.

```
def перевірка(n):
    return n * 2
    print("Цей рядок ніколи не виконається")
```

Це не недолік, а зручність. Завдяки цьому функція може вийти раніше, якщо відповідь уже зрозуміла:

```
def оцінка_словами(бал):
    if бал >= 10:
        return "Високий рівень"
    if бал >= 7:
        return "Достатній рівень"
    return "Потрібно попрацювати"
```

Тут `else` навіть не потрібен: якщо перший `return` спрацював, до другого справа не дійде.

> 📝 **`return` одразу завершує функцію.** Рядки після нього не виконуються.
> Функція може мати кілька `return` — спрацює той, до якого дійде виконання.

> ❓ **Скільки `return` може бути у функції?**
>
> *Очікуємо:* скільки завгодно, але спрацює лише один — той, до якого дійде виконання.

### Блок 4. Що можна повертати

Повертати можна що завгодно: число, текст, список, значення `True` чи `False`.

```
def парне(n):
    return n % 2 == 0

if парне(10):
    print("Так")
```

Тут функція повертає результат порівняння, тобто `True` або `False`, і її можна поставити прямо в умову.

Можна повернути й цілий список:

```
def парні_до(n):
    результат = []
    for i in range(2, n + 1, 2):
        результат.append(i)
    return результат
```

Правило вибору просте. Якщо функція щось **обчислює** — вона повертає. Якщо щось **оформлює** для людини — вона друкує. Змішувати в одній функції обидва завдання не варто.

> 📝 **Повертати можна що завгодно:** число, текст, `True`/`False`, список.
> Функція, яка **обчислює**, повертає результат. Функція, яка **оформлює**, друкує.

> ❓ **Функція рахує середній бал списку. Вона має друкувати чи повертати?**
>
> *Очікуємо:* повертати, бо вона обчислює.


### Блок 5. Функція приймає список

Параметром може бути не лише число чи текст, а й цілий список.

```
def середній_бал(оцінки):
    return sum(оцінки) / len(оцінки)

мої = [10, 7, 11, 9]
print(середній_бал(мої))
```

Функція нічого не знає про те, скільки там оцінок і чиї вони. Вона працює з будь-яким списком — і саме тому її можна викликати для різних предметів, різних учнів, різних класів.

Це і є головна цінність функції: вона описує **спосіб**, а не конкретний випадок.

> 📝 **Параметром функції може бути список.** Така функція працює з будь-яким списком, незалежно від його довжини та вмісту.

> ❓ **Функція `середній_бал` написана для списку з чотирьох оцінок. Чи спрацює вона для списку з двадцяти?**
>
> *Очікуємо:* так, вона не залежить від довжини.

### Блок 6. Функція повертає список

Так само функція може віддати цілий список.

```
def високі_оцінки(оцінки):
    результат = []
    for о in оцінки:
        if о >= 10:
            результат.append(о)
    return результат

найкращі = високі_оцінки([10, 7, 11, 9, 12])
print(найкращі)        → [10, 11, 12]
```

Це прийом відбору з уроку 16, загорнутий у функцію. Тепер його можна застосувати до будь-якого списку одним рядком.

Зверніть увагу: порожній список створюється **всередині** функції. Кожен виклик починає з чистого аркуша, і попередні результати не змішуються.

> 📝 **Функція може повертати список.** Новий список створюють **усередині** функції, наповнюють у циклі й повертають через `return`.

> ❓ **Чому порожній список створюють усередині функції, а не зовні?**
>
> *Очікуємо:* щоб кожен виклик починався з чистого списку й результати не змішувалися.

### Блок 7. Декомпозиція

Тепер головне. Розбити задачу на функції — це не механічна дія, а спосіб думати.

Порядок такий:

1. Описати задачу словами по кроках
2. Кожен крок, який можна назвати одним дієсловом, стає функцією
3. Основна частина програми — це просто перелік викликів

Візьмімо тест. Описуємо словами: привітатися, поставити п'ять питань і порахувати бали, показати результат. Три кроки — три функції.

```
def показати_привітання():
    print("=" * 30)
    print("ТЕСТ З ІНФОРМАТИКИ")
    print("=" * 30)

def провести_тест():
    бали = 0
    # ... п'ять питань ...
    return бали

def показати_результат(бали):
    print(f"Ваш результат: {бали} з 5")
    # ... рівень словами ...

показати_привітання()
результат = провести_тест()
показати_результат(результат)
```

Правило перевірки: якщо основну частину програми не видно на одному екрані, розбиття зроблено погано.

> 📝 **Декомпозиція** — розбиття задачі на частини.
> Описати задачу по кроках → кожен крок стає функцією → основна частина програми стає переліком викликів.
> **Основна частина програми має вміщатися на одному екрані.**

> ❓ **Скільки функцій вийде із задачі, описаної чотирма кроками?**
>
> *Очікуємо:* приблизно чотири, по одній на крок.

### Блок 8. Функція викликає функцію

Функції можна складати одна з одної — так із простих цеглинок будують складне.

```
def середній_бал(оцінки):
    return sum(оцінки) / len(оцінки)

def рівень(бал):
    if бал >= 10:
        return "Високий"
    if бал >= 7:
        return "Достатній"
    return "Середній"

def показати_підсумок(оцінки):
    середнє = середній_бал(оцінки)
    print(f"Середній бал: {середнє:.1f} — {рівень(середнє)}")

показати_підсумок([10, 7, 11, 9])
```

Тут `показати_підсумок` користується двома іншими функціями й не повторює їхньої роботи.

Кожна функція при цьому лишається простою й робить одну річ. Саме так пишуть великі програми: не одним довгим текстом, а десятками маленьких функцій, які викликають одна одну.

> 📝 **Функція може викликати інші функції.** Так із простих функцій складають складніші, і кожна лишається короткою.

> ❓ **Функція `показати_підсумок` рахує середнє сама чи звертається до іншої функції?**
>
> *Очікуємо:* звертається до `середній_бал`, тому й не повторює її код.

## 7. Якщо лишився час

**Найпоширеніша помилка початківців у світі.** Плутанина між `print` і `return` посідає перше місце в усіх списках типових помилок при вивченні програмування. Причина психологічна: на екрані все виглядає правильно, тому здається, що функція працює. Помилка виявляється лише тоді, коли результат треба використати далі. Саме тому на цю тему витрачають цілий урок.

**Чому функцію без return теж називають функцією.** Строго кажучи, це процедура — вона щось робить, але значення не дає. У деяких мовах, наприклад у Pascal, процедури й функції описують різними словами. Python їх не розрізняє: усе зветься функцією, а та, що нічого не повертає, повертає `None`.

**Скільки рядків має бути у функції.** У різних командах правила різні, але цифри схожі: від десяти до двадцяти рядків, максимум п'ятдесят. Причина не в естетиці, а в тому, що людина здатна тримати в голові приблизно сім речей одночасно. Функція, яка не поміщається в цю межу, стає джерелом помилок незалежно від того, наскільки гарно вона написана.

**Побічні ефекти.** Ситуація з бонусу 5 має назву: функція, яка змінює щось за межами себе, має побічний ефект. Такі функції складніші для розуміння, бо, дивлячись на виклик, неможливо здогадатися, що саме зміниться. Тому в сучасному програмуванні їх намагаються обмежувати: функція або обчислює й повертає, або явно щось змінює, і з імені зрозуміло, що саме.
