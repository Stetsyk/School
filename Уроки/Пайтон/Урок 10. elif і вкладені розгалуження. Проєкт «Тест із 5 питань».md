if бал <= 3:

## 2. Пояснення (12-15 хв)

### Блок 1. Команда elif

`elif` — це скорочення від «else if», тобто «інакше якщо». Вона дозволяє поставити наступне питання, коли попереднє дало хибну відповідь.

```
if бал <= 3:
    print("Початковий")
elif бал <= 6:
    print("Середній")
elif бал <= 9:
    print("Достатній")
else:
    print("Високий")
```

Усі гілки на одному рівні, драбина зникла.

Будова така: спершу обов'язково один `if`, потім скільки завгодно `elif`, і наприкінці необов'язковий `else` для всіх решти випадків.

> 📝 **Ланцюжок умов:**
>
> ```
> if умова1:
>     дія1
> elif умова2:
>     дія2
> elif умова3:
>     дія3
> else:
>     дія для решти
> ```
>
> `elif` — скорочення від «інакше якщо». Спершу завжди `if`, наприкінці необов'язковий `else`.

> ❓ **Скільки `elif` можна поставити в одному ланцюжку?**
>
> *Очікуємо:* скільки завгодно, обмежень немає.

### Блок 2. Перевірка зупиняється на першій істинній

Ось найважливіше про `elif`. Python перевіряє умови **згори вниз** і, щойно знаходить істинну, виконує її гілку й **пропускає весь залишок ланцюжка**.

Тому в ланцюжку завжди виконується не більше однієї гілки — навіть якщо істинних умов кілька.

Порівняйте при `бал = 2`:

```
if бал <= 3:              if бал <= 3:
    print("Початковий")       print("Початковий")
elif бал <= 6:            if бал <= 6:
    print("Середній")         print("Середній")
```

Ліворуч виведеться тільки `Початковий`. Праворуч — обидва рядки, бо це два незалежні `if`, і кожен перевіряється сам по собі.

> 📝 **Умови в ланцюжку перевіряються згори вниз.** Виконується гілка **першої істинної** умови, решта не перевіряються зовсім.

> ❓ **При `бал = 2` скільки повідомлень виведе ланцюжок із чотирьох гілок?**
>
> *Очікуємо:* одне — від першої істинної умови.

### Блок 3. Порядок умов має значення

З попереднього правила випливає наслідок, на якому спотикаються всі: **якщо переставити умови місцями, програма почне працювати неправильно**.

Ось приклад із перевернутим порядком:

```
if бал <= 9:
    print("Достатній")
elif бал <= 6:
    print("Середній")
elif бал <= 3:
    print("Початковий")
```

При балі 2 виведеться `Достатній`. Бо `2 <= 9` — істина, і Python зупинився на першій умові, не дійшовши до потрібної.

Правило просте: **умови розставляють від найвужчої до найширшої**. Спершу найсуворіші перевірки, потім загальніші.

> 📝 **Порядок умов у ланцюжку важливий.** Умови ставлять від найвужчої до найширшої, інакше загальна умова перехопить усі випадки.

> ❓ **Чому в ланцюжку `if бал <= 9` не можна ставити першим?**
>
> *Очікуємо:* ця умова істинна й для маленьких балів, тому решта гілок ніколи не спрацюють.

### Блок 4. Вкладені розгалуження

Іноді питання виникає **всередині** відповіді на попереднє. Тоді один `if` ставлять усередину іншого — з подвійним відступом.

```
if картка_дійсна:
    if 8 <= година <= 18:
        print("Двері відчинено")
    else:
        print("Неробочий час")
else:
    print("Картка недійсна")
```

Тут друге питання має сенс тільки для тих, у кого картка дійсна. Це і є ознака вкладеності: наступна перевірка стосується не всіх, а лише однієї гілки.

Коли ж обидві умови стосуються одного й того самого випадку, вкладеність не потрібна — достатньо `and`. Порівняйте:

```
if вік >= 14 and зріст >= 140:      # ці дві умови рівноправні
```

І остання порада: глибше трьох рівнів вкладеності краще не заходити. Якщо вийшло — задачу треба переписати.

> 📝 **Вкладене розгалуження** — `if` усередині `if`, із подвійним відступом. Потрібне, коли друга перевірка стосується лише однієї гілки.
> Якщо умови рівноправні — беруть `and`, а не вкладеність.

> ❓ **Треба перевірити вік і зріст для атракціону. Вкладеність чи `and`?**
>
> *Очікуємо:* `and`, бо обидві умови стосуються одного випадку.


### Блок 5. Накопичувач балів

Тест — це та сама змінна-лічильник, яку ми робили на уроці 4, тільки збільшується вона не завжди, а за умовою.

```
бали = 0

відповідь = input("Столиця України? ")
if відповідь == "Київ":
    бали += 1

відповідь = input("Скільки днів у тижні? ")
if відповідь == "7":
    бали += 1

print(f"Ваш результат: {бали} з 2")
```

Три речі варто помітити. Змінна `бали` обнуляється **до** всіх питань. Одна й та сама змінна `відповідь` використовується повторно — попередня відповідь уже не потрібна. І відповідь порівнюється як текст, тому сімка теж у лапках.

> 📝 **Схема тесту:** обнулити лічильник балів → питання → перевірка через `if` → `бали += 1` за правильну відповідь → підсумок.
> Лічильник обнуляють **один раз на початку**, до всіх питань.

> ❓ **Що станеться, якщо написати `бали = 0` перед кожним питанням?**
>
> *Очікуємо:* лічильник щоразу скидатиметься, і в кінці буде максимум один бал.

### Блок 6. Шкала оцінювання

Коли бали пораховані, залишається перевести їх в оцінку. Це ланцюжок `elif` з першої половини уроку.

```
if бали == 5:
    print("Відмінно! Усе правильно")
elif бали >= 3:
    print("Добре, але є над чим попрацювати")
else:
    print("Варто повторити тему")
```

Умови, як домовлялися, від найвужчої до найширшої.

> 📝 **Шкала результату** будується ланцюжком `if-elif-else` за кількістю балів, від найвищого результату до найнижчого.

> ❓ **Чому гілку `бали >= 3` не можна поставити першою?**
>
> *Очікуємо:* вона істинна й для п'яти балів, тому найкращий результат ніколи не з'явиться.

### Блок 7. Дрібниці, які роблять програму дорослою

Три речі, які відрізняють хорошу програму від просто працюючої.

**Порівняння без урахування регістру.** Учень напише `київ` з малої, і програма зарахує помилку. Виправляється методом `.lower()`, який переводить введене в малі літери:

```
if відповідь.lower() == "київ":
```

**Захист від ділення на нуль.** Якщо десь ділите — перевірте дільник:

```
if кількість == 0:
    print("Немає питань")
else:
    print(бали / кількість * 100)
```

**Відсоток правильних.** Просте обчислення, яке робить результат зрозумілішим: `бали / 5 * 100`.

> 📝 **Метод `.lower()`** переводить текст у малі літери. Використовують при порівнянні відповідей, щоб регістр не впливав: `if відповідь.lower() == "київ":`
> Перед діленням завжди перевіряють, чи дільник не нуль.

> ❓ **Навіщо потрібен `.lower()` у перевірці відповіді?**
>
> *Очікуємо:* щоб `Київ`, `київ` і `КИЇВ` зараховувались однаково.

## 3. Перевірка розуміння (4-6 хв)

1. **Що означає `elif`?**
   «Інакше якщо» — наступне питання, коли попереднє дало хибну відповідь.

2. **Скільки гілок виконається в ланцюжку `if-elif-else`?**
   Не більше однієї — гілка першої істинної умови.

3. **Чому порядок умов важливий?**
   Перевірка зупиняється на першій істинній, тому широка умова перехопить випадки, призначені для вужчих.

4. **Коли потрібна вкладеність, а коли `and`?**
   Вкладеність — коли друга перевірка стосується лише однієї гілки. `and` — коли обидві умови рівноправні.

5. **Чи обов'язковий `else` наприкінці ланцюжка?**
   Ні, він необов'язковий.

6. **Де в програмі-тесті обнуляють лічильник балів?**
   Один раз на самому початку, до всіх питань.

7. **Як додати бал за правильну відповідь?**
   `бали += 1` усередині `if`.

8. **Чим будують шкалу результату?**
   Ланцюжком `if-elif-else`.

9. **Що робить `.lower()`?**
   Переводить текст у малі літери, щоб регістр не впливав на порівняння.

10. **Що треба перевірити перед діленням?**
   Що дільник не дорівнює нулю.

#### ✅ Відповіді до бонусів

**Бонус 1.** ланцюжок дає рівно один результат із п'яти можливих гілок. Чотири окремі `if` можуть дати від нуля до чотирьох повідомлень одночасно — це і є принципова різниця між ланцюжком і незалежними перевірками.

**Бонус 2.** Умови стоять у неправильному порядку. Перевірка зупиняється на першій істинній, а `бал >= 4` істинна й для 12, тому всі, хто має 4 і більше, отримають `середній`, а гілки `достатній` і `високий` не спрацюють ніколи. Правильно — від найсуворішої умови до найм'якшої: спершу `>= 10`, потім `>= 7`, потім `>= 4`.

**Бонус 3.** У найкращому випадку одну — коли справдилася перша умова. У найгіршому п'ять, коли підходить остання гілка або жодна. Щоб пришвидшити, найчастіші випадки ставлять **угору**: тоді більшість запусків обірветься на першій-другій перевірці. Це працює тільки тоді, коли умови не перекриваються, інакше перестановка змінить сам результат, як у бонусі 3.

**Бонус 4.** `if відповідь.strip().lower() == "б":`. Метод `strip` прибирає пробіли по краях, `lower` переводить у малі літери. Обидва можна застосовувати підряд.

**Бонус 5.** через `or` з кількома варіантами:
```

```
Коротший спосіб через список ми вивчимо на уроці 15: `if відповідь.lower() in ["київ", "киев"]:`

**Бонус 6.** Відсоток — це частка правильних, помножена на 100: `print(f"Результат: {бали / 5 * 100:.1f}%")`. Для трьох правильних вийде `60.0%`. Ділити треба саме на кількість питань, а не на 5 числом: якщо ви колись додасте шосте питання, формулу з числом доведеться шукати й правити, тому кількість краще тримати в змінній.

**Бонус 7.** Потрібні два методи підряд: `.strip()` прибирає пробіли з країв, `.lower()` переводить у малі літери.
```

if відповідь == "київ":
    бали += 1
```
Порядок тут не важливий, але зразок для порівняння теж має бути з малих літер. Це та дрібниця, через яку учні найчастіше отримують нуль за правильну відповідь.

## 7. Якщо лишився час

**Чому саме `elif`, а не `else if`.** У більшості мов пишуть два окремі слова, і кожен наступний варіант відсувається правіше — та сама драбина, з якої ми починали урок. Python скоротив це до одного слова спеціально, щоб ланцюжок лишався пласким. Дрібниця, але саме завдяки їй код на Python рідко з'їжджає за край екрана.

**Конструкція, якої в Python довго не було.** У багатьох мовах для вибору з багатьох варіантів існує окрема команда — `switch`. Python обходився без неї тридцять років, бо `elif` покриває майже всі випадки. Схожа конструкція `match` з'явилася лише у 2021 році, у версії 3.10, і призначена для складніших задач, ніж просте порівняння чисел.

**Скільки коштує неправильна перевірка відповіді.** У великих онлайн-тестах відповідь порівнюють не просто через рівність: враховують зайві пробіли, різні лапки, кириличну й латинську літеру «і», регістр. Один із найвідоміших випадків — коли тисячі учнів отримали нуль за правильну відповідь лише тому, що набрали її з великої літери. Саме через це ми додали `.lower()`.

**Чому питання в тестах перемішують.** Якщо всі проходять тест в однаковому порядку, відповіді швидко розходяться по класу. Тому в справжніх системах питання й варіанти щоразу перемішують випадковим чином. Ми навчимося це робити на уроці 22, коли з'явиться модуль `random`.
