## 1. Вступ-гачок (2-3 хв)

Подумайте про гру, у яку ви грали годинами. Чому від неї неможливо відірватися?

У розробників ігор є два старі секрети.

Перший: **друга спроба**. Коли ви програли через дурну помилку, хочеться одразу ж спробувати ще раз. Тому в іграх є життя: один промах — ще не кінець.

Другий: **гра поступово стає складнішою**. Якщо гра весь час легка — нудно. Якщо одразу дуже важка — кидаєш через хвилину. А якщо спершу легко, а потім щоразу трохи важче, ви весь час на межі своїх сил. Саме тоді гра затягує.

Наш Bounce зараз не має ні того, ні іншого: один промах — і все, а м'яч летить однаково від початку до кінця. Сьогодні ми додамо три життя, рівні й прискорення. А в другій половині уроку кожен зробить **свою** версію гри й дасть у неї зіграти всьому класу.

## 2. Пояснення (8-10 хв)

### Блок 1. Три життя

Заводимо змінну `життя = 3`. Тепер гра йде не вічно, а **поки є життя**. Тому замість `while True` і `break` пишемо умову прямо в циклі:

```
while життя > 0:
    ...
```

Коли життя закінчаться, умова стане хибною, і цикл зупиниться сам.

Життя гравець має бачити на екрані. Покажемо їх сердечками. Тут знадобиться старий трюк: рядок можна **множити на число**.

```
"♥" * 3     # дає ♥♥♥
"♥" * 1     # дає ♥
"♥" * 0     # дає порожній рядок
```

Тому сердечка на табло оновлюються одним рядком: `полотно.itemconfig(серця, text="♥" * життя)`.

> 📝 **Життя:** гра йде, `while життя > 0:`. Промах — `життя = життя - 1`.
> Сердечка на екрані: `"♥" * життя` — рядок, помножений на число, повторюється.

> ❓ **Що покаже табло, коли `життя` дорівнює 0?**
>
> *Очікуємо:* нічого, бо `"♥" * 0` — порожній рядок.

### Блок 2. Друга спроба

Коли м'яч упав, гра тепер не закінчується. Треба повернути м'яч нагору й дати гравцю секунду, щоб приготуватися.

Повернути фігуру в потрібне місце допоможе вже знайома команда `coords`. Досі ми її **питали**, де м'яч. Але якщо дати їй ще й чотири числа, вона **поставить** м'яч туди:

```
if y2 >= 400:
    життя = життя - 1
    полотно.itemconfig(серця, text="♥" * життя)
    полотно.coords(мяч, 285, 50, 315, 80)
    полотно.update()
    time.sleep(1)
```

Пауза на секунду — щоб гравець побачив, що втратив життя, і встиг перевести подих.

> 📝 `полотно.coords(мяч)` — **дізнатися**, де м'яч.
> `полотно.coords(мяч, 285, 50, 315, 80)` — **поставити** м'яч у задане місце.

> ❓ **Чим `move(мяч, 0, -300)` відрізняється від `coords(мяч, 285, 50, 315, 80)`?**
>
> *Очікуємо:* `move` зсуває на відстань від того місця, де м'яч був, а `coords` ставить у точно задану точку.

### Блок 3. Рівні й прискорення

Кожні 5 впійманих м'ячів — новий рівень, і м'яч летить швидше.

Як дізнатися, що рахунок дійшов до 5, 10, 15 і так далі? Ці числа діляться на 5 **без остачі**. А остачу ми вміємо рахувати знаком `%`:

```
if рахунок % 5 == 0:
    рівень = рівень + 1
    dx = dx * 1.2
    dy = dy * 1.2
```

Чому швидкість **множимо** на 1.2, а не додаємо одиницю? Бо `dx` буває від'ємним, коли м'яч летить ліворуч. Якщо до −5 додати 1, вийде −4, і м'яч **сповільниться**. А −5 помножити на 1.2 — це −6: м'яч летить у той самий бік, тільки швидше. Множення не чіпає знак.

> 📝 **Новий рівень** кожні 5 очок: `if рахунок % 5 == 0:`
> **Прискорення** — множенням: `dx = dx * 1.2`, `dy = dy * 1.2`. Множення зберігає напрямок, а додавання може сповільнити м'яч.

> ❓ **На якому рахунку гравець перейде на третій рівень?**
>
> *Очікуємо:* на 10, бо другий рівень починається з 5, а третій — з 10.

### Блок 4. Гра має відповідати

Гравцю приємно, коли гра **реагує** на кожен його успіх: щось спалахує, міняє колір, звучить. Розробники називають це «соковитістю» гри. Без неї навіть хороша гра здається мертвою.

Найпростіше, що ми вже вміємо, — міняти колір м'яча при кожному впійманні:

```
полотно.itemconfig(мяч, fill=random.choice(кольори))
```

Цей рядок ставимо всередину умови впіймання. Дрібниця, а гра одразу оживає. На проєкті ви зможете придумати свої такі дрібниці.

> 📝 **Соковитість гри** — маленькі реакції на дії гравця: зміна кольору, напис, спалах. Вони роблять гру живою.

> ❓ **Куди в програмі треба поставити рядок зміни кольору, щоб м'яч мінявся саме при впійманні?**
>
> *Очікуємо:* усередину умови, яка перевіряє, що м'яч торкнувся ракетки.

import tkinter
import time
import random

вікно = tkinter.Tk()
вікно.title("Bounce")
полотно = tkinter.Canvas(вікно, width=600, height=400, bg="midnightblue")
полотно.pack()

табло = полотно.create_text(120, 20, text="Рахунок: 0   Рівень: 1",
                            fill="white", font=("Arial", 14))
серця = полотно.create_text(540, 20, text="♥♥♥",
                            fill="red", font=("Arial", 18))
мяч = полотно.create_oval(100, 50, 130, 80, fill="orange")
ракетка = полотно.create_rectangle(250, 370, 350, 385, fill="white")


def ліворуч(подія):
    x1, y1, x2, y2 = полотно.coords(ракетка)
    if x1 > 0:
        полотно.move(ракетка, -25, 0)


def праворуч(подія):
    x1, y1, x2, y2 = полотно.coords(ракетка)
    if x2 < 600:
        полотно.move(ракетка, 25, 0)


полотно.bind("<Left>", ліворуч)
полотно.bind("<Right>", праворуч)
полотно.focus_set()

кольори = ["orange", "yellow", "lime", "cyan", "violet", "red"]
dx = 5
dy = 4
рахунок = 0
рівень = 1
життя = 3

while життя > 0:
    полотно.move(мяч, dx, dy)
    x1, y1, x2, y2 = полотно.coords(мяч)

    if x1 <= 0 or x2 >= 600:
        dx = -dx
    if y1 <= 0:
        dy = -dy

    if ракетка in полотно.find_overlapping(x1, y1, x2, y2) and dy > 0:
        dy = -dy
        рахунок = рахунок + 1
        полотно.itemconfig(мяч, fill=random.choice(кольори))
        # кожні 5 очок — новий рівень, м'яч швидшає
        if рахунок % 5 == 0:
            рівень = рівень + 1
            dx = dx * 1.2
            dy = dy * 1.2
        полотно.itemconfig(табло, text=f"Рахунок: {рахунок}   Рівень: {рівень}")

    # м'яч упав — мінус одне життя, м'яч повертається нагору
    if y2 >= 400:
        життя = життя - 1
        полотно.itemconfig(серця, text="♥" * життя)
        полотно.coords(мяч, 285, 50, 315, 80)
        полотно.update()
        time.sleep(1)

    полотно.update()
    time.sleep(0.02)

полотно.create_text(300, 200, text=f"Гру завершено!\nРахунок: {рахунок}",
                    fill="white", font=("Arial", 30), justify="center")
вікно.mainloop()
```

#### ✅ Відповіді до бонусів

**Бонус 1.** Усередині умови впіймання:

**Бонус 2.** Усередині `if рахунок % 5 == 0`:
```
р1, р2, р3, р4 = полотно.coords(ракетка)
if р3 - р1 > 40:
    полотно.coords(ракетка, р1 + 10, р2, р3 - 10, р4)
```
Пастка: після вкорочення краї ракетки вже не кратні 25, і стара перевірка меж пропускає її за край екрана. Надійніше перевіряти, чи вистачає місця на цілий крок: ліворуч — `if x1 >= 25`, праворуч — `if x2 <= 575`.

**Бонус 3.** Рахуємо, наскільки центр м'яча зміщений від центру ракетки, і робимо з цього нове `dx`:
```

центр_мяча = (x1 + x2) / 2
центр_ракетки = (р1 + р3) / 2

Ракетка завширшки 100, тож зміщення буває від −65 до 65, а `dx` — приблизно від −8 до 8. Саме так зроблено в справжніх іграх такого типу, інакше гравець не може цілитися.

У циклі гри, після перевірки стін:
```
for ф in полотно.find_overlapping(x1, y1, x2, y2):
    if ф in цеглинки:
        полотно.delete(ф)
        цеглинки.remove(ф)
        dy = -dy
        break
if len(цеглинки) == 0:
    break
```
`break` усередині `for` зупиняє лише перебір, щоб м'яч не розвернувся двічі, якщо зачепить дві цеглинки. Другий `break` виходить із циклу гри — це перемога. Фінальний напис після циклу тоді варто зробити різним: якщо цеглинок не лишилося — «Перемога!», інакше «Гру завершено».

## 6. Домашнє завдання

**Завдання.** Доведіть свій Bounce до ладу й дайте зіграти двом людям.

Запишіть у зошит рекорд кожного гравця і що вони порадили змінити. Виберіть одну пораду й утіліть її в грі.

**Якщо комп'ютера вдома немає:** придумайте на папері «Bounce 2.0». Намалюйте екран нової версії з однією новою річчю: перешкодою посередині, бонусом, що падає згори, другим м'ячем або чимось своїм. Опишіть правила словами, а потім запишіть, які змінні й які перевірки в циклі для цього знадобляться.

## 7. Якщо лишився час

**Гра, яку робили два Стіви.** У 1976 році компанія Atari випустила гру Breakout — ту саму, де ракеткою вибивають цеглинки. Над нею працювали двоє молодих хлопців, Стів Джобс і Стів Возняк. Через кілька місяців вони заснували власну компанію і назвали її Apple. Тож ваш бонус із цеглинками має досить відомий родовід.

**Чому саме три життя.** Звичка давати гравцеві три життя прийшла з ігрових автоматів. Автомат заробляв, лише коли гра закінчувалася і людина кидала ще одну монету. Три спроби — це компроміс: достатньо, щоб гравець встиг відчути смак гри, і достатньо мало, щоб гра закінчилася й захотілося ще.
