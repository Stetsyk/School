## 1. Вступ-гачок (2-3 хв)

Минулого уроку наш м'яч літав, міняв кольори й ловив кути. Гарно. Але скажіть чесно: довго на це можна дивитися?

Чим мультик відрізняється від гри? У мультику все вирішено без вас. А в грі ви можете **втрутитися**. І, що найважливіше, ви можете **програти**.

Саме можливість програти робить гру цікавою. Коли м'яч летить до краю, а ракетка ще далеко, серце б'ється швидше. Без цього ризику гра перетворюється на заставку.

Сьогодні ми приберемо в м'яча нижню стіну. Тепер його доведеться ловити ракеткою, яку ви водите стрілками. Не впіймали — гра закінчилася. До кінця уроку кожен матиме гру, у яку можна змагатися з сусідом.

## 2. Пояснення (8-10 хв)

### Блок 1. Програма слухає клавіатуру

Щоб натискання клавіші щось робило, потрібні дві речі: **функція**, яка робить потрібну дію, і **прив'язка** клавіші до цієї функції.

```
def ліворуч(подія):
    полотно.move(ракетка, -25, 0)

def праворуч(подія):
    полотно.move(ракетка, 25, 0)

полотно.bind("<Left>", ліворуч)
полотно.bind("<Right>", праворуч)
полотно.focus_set()
```

Команда `bind` каже полотну: «коли натиснуть стрілку вліво — виклич функцію `ліворуч`». Ім'я функції пишуть **без дужок**. З дужками функція спрацює один раз при запуску, а потім клавіша не робитиме нічого.

У такої функції обов'язково є параметр `подія` — через нього програма передає відомості про натискання. Нам вони поки не потрібні, але без параметра буде помилка.

Рядок `focus_set()` каже, що слухати клавіатуру має саме полотно. Без нього стрілки не працюватимуть.

> 📝 **Керування клавішами:**
>
> ```
> def ліворуч(подія):
>     полотно.move(ракетка, -25, 0)
>
> полотно.bind("<Left>", ліворуч)
> полотно.focus_set()
> ```
>
> Ім'я функції в `bind` — **без дужок**. У функції обов'язковий параметр `подія`.

> ❓ **Що станеться, якщо написати `полотно.bind("<Left>", ліворуч())`?**
>
> *Очікуємо:* функція спрацює один раз при запуску, а стрілка не працюватиме.

### Блок 2. Ракетка не тікає з екрана

Якщо довго тиснути стрілку, ракетка поїде за край і зникне. Треба перед рухом перевірити, чи є куди їхати.

```
def ліворуч(подія):
    x1, y1, x2, y2 = полотно.coords(ракетка)
    if x1 > 0:
        полотно.move(ракетка, -25, 0)
```

Це той самий `coords`, що й у м'яча. Якщо лівий край ракетки вже біля нуля, рух ліворуч просто не відбувається. Для правої стрілки перевіряємо правий край: `if x2 < 600`.

> 📝 **Межі ракетки:** перед рухом дізнаємось, де ракетка, через `coords`.
> Ліворуч їдемо, лише якщо `x1 > 0`. Праворуч — лише якщо `x2 < 600`.

> ❓ **Ракетка стоїть на `[500, 370, 600, 385]`. Гравець тисне стрілку вправо. Що буде?**
>
> *Очікуємо:* нічого, бо `x2` дорівнює 600 і умова `x2 < 600` хибна.

### Блок 3. Чи впіймали м'яч?

Тепер найцікавіше: як програма зрозуміє, що м'яч торкнувся ракетки?

У полотна є команда-шпигун `find_overlapping`. Ви даєте їй прямокутник, а вона відповідає, **які фігури його торкаються**. Даємо їй прямокутник м'яча й питаємо, чи є серед відповідей ракетка:

```
if ракетка in полотно.find_overlapping(x1, y1, x2, y2) and dy > 0:
    dy = -dy
    рахунок = рахунок + 1
```

Слово `in` ви вже знаєте зі списків: воно перевіряє, чи є значення серед інших.

А навіщо `and dy > 0`? Додатне `dy` означає, що м'яч летить **вниз**. Відбивати його треба тільки тоді. Інакше, якщо м'яч зачепить ракетку боком, він почне розвертатися на кожному кадрі й застрягне в ній.

> 📝 **Зіткнення:** `полотно.find_overlapping(x1, y1, x2, y2)` — номери всіх фігур, які торкаються прямокутника.
> М'яч упіймано: `ракетка in полотно.find_overlapping(x1, y1, x2, y2) and dy > 0`.

> ❓ **Навіщо в умові впіймання перевіряти `dy > 0`?**
>
> *Очікуємо:* щоб відбивати м'яч, лише коли він летить униз, і він не застрягав у ракетці.

### Блок 4. Програш

Залишилося головне — можливість програти. Для цього в перевірці стін прибираємо нижню стіну: м'яч відбивається від лівої, правої й верхньої, а знизу більше нічого немає.

Якщо м'яч долетів до дна, цикл треба зупинити. Для цього є знайома команда `break`:

```
if y2 >= 400:
    break
```

Після циклу виводимо напис із результатом, і наприкінці ставимо `вікно.mainloop()`, щоб вікно не закрилося саме.

> 📝 **Програш:** нижньої стіни немає. Якщо `y2 >= 400` — `break`, цикл зупиняється.
> Після циклу — напис «Гру завершено» і `вікно.mainloop()`.

> ❓ **Що станеться, якщо після циклу забути `вікно.mainloop()`?**
>
> *Очікуємо:* програма закінчиться й вікно закриється, напис ніхто не побачить.

Крок 3. Приберіть нижню стіну, додайте впіймання й програш. Повна програма:

```
import tkinter
import time

вікно = tkinter.Tk()
вікно.title("Bounce")
полотно = tkinter.Canvas(вікно, width=600, height=400, bg="midnightblue")
полотно.pack()

табло = полотно.create_text(300, 20, text="Рахунок: 0",
                            fill="white", font=("Arial", 14))
мяч = полотно.create_oval(100, 50, 130, 80, fill="orange")
ракетка = полотно.create_rectangle(250, 370, 350, 385, fill="white")


def ліворуч(подія):
    x1, y1, x2, y2 = полотно.coords(ракетка)
    if x1 > 0:
        полотно.move(ракетка, -25, 0)


def праворуч(подія):
    x1, y1, x2, y2 = полотно.coords(ракетка)
    if x2 < 600:
        полотно.move(ракетка, 25, 0)


полотно.bind("<Left>", ліворуч)
полотно.bind("<Right>", праворуч)
полотно.focus_set()

dx = 5
dy = 4
рахунок = 0

while True:
    полотно.move(мяч, dx, dy)
    x1, y1, x2, y2 = полотно.coords(мяч)

    # стіни: ліва, права і верхня
    if x1 <= 0 or x2 >= 600:
        dx = -dx
    if y1 <= 0:
        dy = -dy

    # ракетка: чи торкається вона м'яча?
    if ракетка in полотно.find_overlapping(x1, y1, x2, y2) and dy > 0:
        dy = -dy
        рахунок = рахунок + 1
        полотно.itemconfig(табло, text=f"Рахунок: {рахунок}")

    # м'яч упав на дно — кінець гри
    if y2 >= 400:
        break

    полотно.update()
    time.sleep(0.02)

полотно.create_text(300, 200, text=f"Гру завершено!\nРахунок: {рахунок}",
                    fill="white", font=("Arial", 30), justify="center")
вікно.mainloop()
```

Символ `\n` у тексті переносить рядок, тому рахунок стоїть під написом.

## 7. Якщо лишився час

**Невидимі прямокутники.** Ви помітили, що м'яч у нас круглий, а `find_overlapping` перевіряє прямокутник навколо нього? У справжніх іграх так само: майже кожен персонаж обведений невидимою рамкою, яку називають хітбоксом. Зіткнення рахують саме по рамці, бо це в сотні разів швидше, ніж по точній формі. Тому іноді в іграх куля «влучає», хоча на екрані пролетіла поруч, — гравці навіть знімають про це смішні відео.

**Чому ракетка рушає із затримкою.** Якщо затиснути стрілку, ракетка зрушить, на мить зупиниться й лише тоді поїде. Це не помилка нашої програми, а звичка клавіатури: так само поводиться затиснута літера в текстовому редакторі. Перше натискання, пауза, потім повтор. У справжніх іграх роблять інакше: програма запам'ятовує, що клавіша **затиснута**, і рухає героя на кожному кадрі, поки її не відпустять.
