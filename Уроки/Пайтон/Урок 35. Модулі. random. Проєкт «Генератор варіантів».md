## 2. Пояснення (8-10 хв)

### Блок 1. Модулі

Модуль — це набір готових функцій, які написав хтось інший. У Python їх сотні, і більшість уже встановлені разом із мовою.

Щоб скористатися модулем, його підключають командою `import` на самому початку програми.

```
import math

print(math.sqrt(16))     → 4.0
print(math.pi)           → 3.141592653589793
print(math.ceil(4.2))    → 5     округлення вгору
print(math.floor(4.8))   → 4     округлення вниз
```

Звертаються так: спершу ім'я модуля, потім крапка, потім функція. Крапка тут означає те саме, що в методах списків: «візьми з цього те».

Модуль `math` містить усе для математики: корінь, число пі, тригонометрію, округлення в обидва боки.

> 📝 **Модуль** — набір готових функцій. Підключається командою `import` на початку програми.
> Звернення: `модуль.функція()`, наприклад `math.sqrt(16)`.

> ❓ **Де в програмі пишуть команду `import`?**
>
> *Очікуємо:* на самому початку, до всього іншого коду.

### Блок 2. Модуль random: числа

Модуль `random` дає випадкові значення.

```
import random

print(random.randint(1, 6))     # випадкове ціле від 1 до 6
```

`randint` — від *random integer*, випадкове ціле. І одразу важлива відмінність від `range`: **обидві межі входять**. `randint(1, 6)` може дати і 1, і 6 — рівно як кубик.

Це часта пастка: у `range(1, 6)` шістки немає, а в `randint(1, 6)` є.

Ще одна функція — `random.random()` — дає дробове число від 0 до 1. Вона знадобиться, коли треба щось із певною ймовірністю.

> 📝 **`random.randint(a, b)`** — випадкове ціле від `a` до `b`, **обидві межі входять**.
> На відміну від `range`, де права межа не входить.
> `random.random()` дає дробове число від 0 до 1.

> ❓ **Які значення може дати `random.randint(1, 3)`?**
>
> *Очікуємо:* 1, 2 або 3.

### Блок 3. random зі списками

Три функції, які працюють зі списками, і різниця між ними важлива.

**`choice`** обирає один випадковий елемент.

```
поради = ["Спробуй ще", "Ти зможеш", "Відпочинь"]
print(random.choice(поради))
```

**`shuffle`** перемішує **сам список**. Нічого не повертає — рівно як `sort` з уроку 28.

```
питання = ["А", "Б", "В", "Г"]
random.shuffle(питання)
print(питання)      → у випадковому порядку
```

**`sample`** обирає кілька різних елементів і повертає новий список. Повторів не буде.

```
print(random.sample(range(1, 50), 6))     # шість різних чисел для лотереї
```

Різниця між `choice` і `sample` принципова: якщо викликати `choice` тричі, один елемент може випасти двічі. `sample` гарантує, що всі різні.

> 📝 **Робота зі списками:**
>
> | Функція | Що робить |
> | --- | --- |
> | `random.choice(список)` | один випадковий елемент |
> | `random.shuffle(список)` | перемішує сам список |
> | `random.sample(список, n)` | n різних елементів, новий список |
>
> `choice` може повторитись, `sample` — ні.

> ❓ **Треба обрати трьох різних чергових із класу. Яка функція потрібна?**
>
> *Очікуємо:* `sample`, бо повтори неприпустимі.

### Блок 4. Випадковість, якої немає

Комп'ютер не вміє бути випадковим. Він виконує команди — і жодна команда не може дати «просто так».

Насправді `random` рахує числа за формулою, беручи за початок щось непередбачуване, наприклад поточний час у мікросекундах. Результат виглядає випадковим і для наших задач ним і є, але формально це **псевдовипадковість**.

Наслідок практичний: для ігор і тестів цього більш ніж достатньо. А от для паролів і банківських систем потрібні спеціальні генератори, які беруть справжній шум із фізичних процесів.

> 📝 **Псевдовипадковість** — числа, обчислені за формулою, які виглядають випадковими. Для ігор і навчальних задач цього достатньо, для захисту даних потрібні спеціальні генератори.

> ❓ **Чому числа з `random` називають псевдовипадковими?**
>
> *Очікуємо:* вони обчислені за формулою, а не взяті нізвідки.

## 5. ⭐ Бонус для сильних

**Бонус 1.** Напишіть генератор випадкового пароля з восьми символів, у якому є і літери, і цифри.

**Бонус 2.** Перевірте, чи справді кубик чесний: киньте його 6000 разів і порахуйте, скільки разів випало кожне число.

**Бонус 3.** Згенеруйте 6 **різних** випадкових чисел від 1 до 49, як у лотереї. Просте `randint` шість разів не годиться. Чому?

**Бонус 4.** Киньте гральний кубик 6000 разів програмою й порахуйте, скільки разів випаде шістка. Яке число ви очікуєте побачити і чому щоразу виходить трохи інше?

#### ✅ Відповіді до бонусів

**Бонус 1.**
```
import random

def пароль(довжина):
    символи = "abcdefghijklmnopqrstuvwxyz0123456789"
    результат = ""
    for i in range(довжина):
        результат += random.choice(символи)
    return результат

print(пароль(8))
```
Головна ідея: `choice` працює не лише зі списком, а й із рядком, бо рядок теж є послідовністю.

**Бонус 2.**
```
import random
лічильники = [0, 0, 0, 0, 0, 0]
for i in range(6000):
    кидок = random.randint(1, 6)
    лічильники[кидок - 1] += 1
print(лічильники)
```
Кожне число має випасти приблизно тисячу разів, з відхиленням у кілька десятків. Головна ідея: індекс списку обчислюється з випадкового числа, тому потрібна поправка на одиницю.

**Бонус 3.** Не годиться, бо `randint` цілком може видати те саме число двічі. Два робочі способи:
```
import random
номери = random.sample(range(1, 50), 6)
```
або вручну, з перевіркою на повтор:
```
номери = []
while len(номери) < 6:
    n = random.randint(1, 49)
    if n not in номери:
        номери.append(n)
```
Перший спосіб коротший, другий показує, що саме відбувається всередині.

**Бонус 4.** Очікуємо приблизно 1000, бо в кубика шість рівноймовірних граней.
```
import random
шісток = 0
for i in range(6000):
    if random.randint(1, 6) == 6:
        шісток += 1
print(шісток)
```
Виходить щоразу інше число, зазвичай від 930 до 1070: випадковість не зобов'язана давати рівно тисячу. Але чим більше кидків, тим ближчою до одної шостої стає **частка** шісток. Це і є закон великих чисел, на якому тримається вся статистика.

## 7. Якщо лишився час

**Скільки модулів у Python.** У стандартній поставці їх понад двісті: робота з датами, файлами, мережею, архівами, звуком, графікою. Це називають «батарейки в комплекті» — принцип, за яким мова має давати все потрібне одразу. А ще існує понад чотириста тисяч додаткових модулів, які пишуть люди з усього світу й викладають у спільне сховище.

**Звідки береться перше випадкове число.** Генератор працює за формулою, і йому потрібне початкове значення, яке називають зерном. За замовчуванням Python бере поточний час із дуже високою точністю. Але зерно можна задати самому — і тоді послідовність «випадкових» чисел буде щоразу однаковою. Це не помилка, а потрібна річ: так перевіряють програми, у яких є випадковість, бо тест має давати той самий результат.
