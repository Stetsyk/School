## 1. Вступ-гачок (2-3 хв)

Задача, яку на співбесідах ставлять програмістам першою.

Є дві склянки. У лівій сік, у правій вода. Треба поміняти вміст місцями — щоб сік опинився праворуч, а вода ліворуч. Як це зробити?

Клас одразу каже: потрібна третя склянка. Правильно. Перелити сік у порожню, налити воду в ліву, потім сік із запасної в праву.

А тепер те саме зі змінними. `a = 3`, `b = 8`, треба поміняти значення місцями. Хтось напише `a = b`, а потім `b = a` — і буде здивований результатом.

Сьогодні розберемо, чому це не працює, і потренуємось розв'язувати задачі, у яких відповідь не отримується одним рядком.

## 2. Пояснення (6-8 хв)

### Блок 1. Обмін значень

Спробуємо наївний спосіб і простежимо його по кроках.

```
a = 3
b = 8
a = b      # тепер a = 8, а трійка зникла назавжди
b = a      # у a лежить 8, тому b теж стає 8
```

Результат: `a = 8`, `b = 8`. Трійки в програмі більше немає — її затерли в третьому рядку.

Правильний спосіб — рівно як зі склянками. Потрібна третя змінна, куди відкладаємо значення на час.

```
c = a      # відклали 3 в запасну змінну
a = b      # a стало 8
b = c      # b взяло 3 із запасної
```

> 📝 **Обмін значень двох змінних** виконується через третю:
> `c = a` · `a = b` · `b = c`
> Без третьої змінної одне зі значень затирається й губиться.

> ❓ **Чому не можна поміняти значення двома рядками `a = b` і `b = a`?**
>
> *Очікуємо:* після першого рядка старе значення `a` вже стерте, і в обох змінних опиняється те саме число.

### Блок 2. Задача в кілька кроків

Коли задача складніша за один вираз, її розв'язують по кроках, і кожен проміжний результат кладуть в окрему змінну з осмисленим іменем.

Приклад: скільки коштує пофарбувати кімнату, якщо стіни 4 на 3 метри, висота 2.5 метра, а фарби треба 0.2 літра на квадратний метр при ціні 180 грн за літр?

```
довжина = 4
ширина = 3
висота = 2.5
периметр = 2 * (довжина + ширина)
площа_стін = периметр * висота
літрів = площа_стін * 0.2
вартість = літрів * 180
print("Треба заплатити:", вартість)
```

Можна було втиснути все в один довгий рядок. Але тоді помилку в ньому не знайти, а так кожен крок видно окремо і його легко перевірити.

> 📝 **Правило багатокрокової задачі:** кожен проміжний результат — в окрему змінну з осмисленим іменем. Так помилку видно одразу, а програму легко читати.

> ❓ **Навіщо розбивати обчислення на кілька рядків, якщо все можна записати одним виразом?**
>
> *Очікуємо:* щоб бачити проміжні результати й швидко знаходити, на якому кроці помилка.

#### ✅ Відповіді до бонусів

**Бонус 1.** Python спершу обчислює всю праву частину й запам'ятовує обидва значення, а вже потім розкладає їх по змінних. Тобто запасне місце все одно є, просто його створює сама мова, а не ми.

**Бонус 2.** одна.
```
t = a
a = b
b = c
c = t
```

**Бонус 3.** Одна.
```
тимч = a
a = b
b = c
c = тимч
```
Ідея та сама, що при обміні двох: зберігаємо те значення, яке буде затерте найпершим, і повертаємо його в кінці ланцюжка.

**Бонус 4.**
```
a = a + b
b = a - b
a = a - b
```
Після першого рядка в `a` лежить сума обох чисел. Другий дістає з неї старе `a` й кладе в `b`. Третій дістає старе `b`. Спосіб працює тільки для чисел, і в справжніх програмах його не використовують: він коротший, зате незрозумілий тому, хто читатиме код.

## 7. Якщо лишився час

**Чому обмін значень питають на співбесідах.** Задача виглядає дитячою, але показує одразу дві речі: чи розуміє людина, що присвоювання затирає старе значення, і чи вміє вона перевірити своє рішення по кроках, а не вгадати. Якщо кандидат одразу пише через третю змінну й пояснює чому — далі можна говорити про серйозніші речі.

**Обмін без третьої змінної.** Для чисел існує хитрий спосіб: `a = a + b`, потім `b = a - b`, потім `a = a - b`. Перевірте на папері — працює. Колись так економили пам'ять, коли її було по кілька кілобайтів. Сьогодні так не пишуть: код заплутаний, а економія жодна.
