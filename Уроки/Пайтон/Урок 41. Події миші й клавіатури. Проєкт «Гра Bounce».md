## 2. Пояснення (8-10 хв)

### Блок 1. Клік миші

Щоб програма реагувала на клік, його прив'язують до функції командою `bind`.

```
def клацнули(подія):
    полотно.create_oval(подія.x - 20, подія.y - 20,
                        подія.x + 20, подія.y + 20, fill="red")

полотно.bind("<Button-1>", клацнули)
полотно.focus_set()
```

Розберемо. `<Button-1>` — це ліва кнопка миші. Друга частина — ім'я функції, яку викликати, і знову **без дужок**, як у кнопці.

Функція-обробник має **один обов'язковий параметр** — зазвичай його називають `подія`. Через нього приходять відомості про те, що сталося: `подія.x` і `подія.y` — координати, де саме клацнули.

Рядок `focus_set()` каже вікну, що саме полотно тепер слухає події. Без нього клавіатура працювати не буде.

> 📝 **Реакція на клік:**
>
> ```
> def клацнули(подія):
>     ...
>
> полотно.bind("<Button-1>", клацнули)
> полотно.focus_set()
> ```
>
> Обробник події має **один параметр**. `подія.x` і `подія.y` — координати кліка.
> Ім'я функції пишуть **без дужок**.

> ❓ **Звідки функція дізнається, у якому місці клацнули?**
>
> *Очікуємо:* з параметра події, через `подія.x` і `подія.y`.

### Блок 2. Клавіатура

Клавіші прив'язують так само, тільки в лапках пишуть назву клавіші.

```
def ліворуч(подія):
    полотно.move(ракетка, -30, 0)

def праворуч(подія):
    полотно.move(ракетка, 30, 0)

полотно.bind("<Left>", ліворуч)
полотно.bind("<Right>", праворуч)
полотно.focus_set()
```

Найпотрібніші назви:

| Запис | Клавіша |
| --- | --- |
| `<Left>` `<Right>` `<Up>` `<Down>` | стрілки |
| `<space>` | пробіл |
| `<Return>` | Enter |
| `<Escape>` | Esc |
| `<Key>` | будь-яка клавіша |

Ще один спосіб керування — стежити за рухом миші. Подія `<Motion>` спрацьовує щоразу, коли миша ворухнулася над полотном, і в неї теж є `подія.x`:

```
def вести(подія):
    полотно.coords(ракетка, подія.x - 50, 370, подія.x + 50, 385)

полотно.bind("<Motion>", вести)
```

Тут з'явилася нова можливість `coords`: якщо передати їй не лише номер фігури, а й чотири нові координати, вона не повідомляє позицію, а **встановлює** її. Зручно, коли треба поставити фігуру точно в потрібне місце, а не зсунути на скільки.

> 📝 **Клавіші:** `полотно.bind("<Left>", функція)`, назва клавіші в кутових дужках.
> **Рух миші:** подія `<Motion>`, координати теж у `подія.x`.
> `полотно.coords(номер, x1, y1, x2, y2)` **ставить** фігуру в задане місце.

> ❓ **Чим `move` відрізняється від `coords` із чотирма числами?**
>
> *Очікуємо:* `move` зсуває на задану відстань, `coords` ставить у задану точку.

### Блок 3. Зіткнення

У грі треба розуміти, коли м'яч торкнувся ракетки. Це перевірка перетину двох прямокутників, і робиться вона порівнянням координат.

Спрощений спосіб, якого нам вистачить: м'яч упіймано, якщо він опустився до рівня ракетки **і** його центр по горизонталі потрапляє в межі ракетки.

```
мяч_поз = полотно.coords(мяч)
ракетка_поз = полотно.coords(ракетка)

центр_мяча = (мяч_поз[0] + мяч_поз[2]) / 2

if мяч_поз[3] >= ракетка_поз[1]:
    if ракетка_поз[0] <= центр_мяча <= ракетка_поз[2]:
        dy = -dy          # відбили
    else:
        програш = True    # пролетів повз
```

Тут `мяч_поз[3]` — нижній край м'яча, `ракетка_поз[1]` — верхній край ракетки. Умова `ракетка_поз[0] <= центр_мяча <= ракетка_поз[2]` — це перевірка діапазону з уроку 15.

> 📝 **Перевірка зіткнення** — це порівняння координат двох фігур.
> М'яч упіймано, якщо його нижній край дійшов до верху ракетки **і** центр м'яча в межах ракетки по горизонталі.

> ❓ **Яку умову перевіряють, щоб зрозуміти, що м'яч пролетів повз ракетку?**
>
> *Очікуємо:* м'яч опустився до рівня ракетки, але його центр поза її межами.

### Блок 4. Головний цикл гри

Тепер складаємо все в одне. Будь-яка гра влаштована однаково: нескінченний цикл, у якому щокроку відбувається одне й те саме.

1. посунути все, що рухається
2. перевірити зіткнення й межі
3. оновити рахунок
4. перемалювати вікно й зробити паузу

```
рахунок = 0
гра_йде = True

while гра_йде:
    полотно.move(мяч, dx, dy)
    # ... перевірки меж і зіткнень ...
    полотно.itemconfig(табло, text=f"Рахунок: {рахунок}")
    полотно.update()
    time.sleep(0.02)

полотно.create_text(300, 200, text="Гру завершено", font=("Arial", 30))
```

Керування при цьому працює **саме собою**: обробники подій викликаються між кроками циклу, бо `update()` не тільки перемальовує вікно, а й опрацьовує накопичені події.

> 📝 **Головний цикл гри:** рух → перевірки → оновлення рахунку → `update()` і пауза.
> Керування працює саме, бо `update()` опрацьовує події між кроками циклу.
> Змінна-прапорець `гра_йде` дозволяє вийти з циклу при програші.

> ❓ **Навіщо в циклі гри потрібна змінна `гра_йде`?**
>
> *Очікуємо:* щоб вийти з нескінченного циклу, коли гравець програв.

## 5. ⭐ Бонус для сильних

**Бонус 1.** Зробіть так, щоб кут відбивання залежав від того, якою частиною ракетки впіймано м'яч.

**Бонус 2.** Додайте вгорі ряд цеглинок, які зникають при влучанні, і зробіть перемогу, коли всі вибиті.

**Бонус 3.** Ракетка керується стрілками, але виїжджає за край екрана. Додайте перевірку меж.

#### ✅ Відповіді до бонусів

**Бонус 1.**
```
відхилення = центр_мяча - (ракетка_поз[0] + ракетка_поз[2]) / 2
dx = відхилення / 10
dy = -dy
```
Ідея: чим далі від середини ракетки впіймано м'яч, тим сильніше він відлітає вбік. Саме так зроблено у справжніх іграх такого типу — інакше гра стає передбачуваною й нецікавою.

**Бонус 2.** цеглинки тримають у списку, а при влучанні прибирають із полотна й зі списку.
```
цеглинки = []
for i in range(10):
    ц = полотно.create_rectangle(20 + i * 56, 30, 70 + i * 56, 50, fill="orange")
    цеглинки.append(ц)
```
У циклі гри перебирають список і перевіряють зіткнення з кожною цеглинкою. При влучанні: `полотно.delete(ц)` і `цеглинки.remove(ц)`. Перемога, коли `len(цеглинки) == 0`.
Обережно: видаляти зі списку прямо під час його перебору небезпечно — саме про це ми говорили на уроці 25. Тому влучені цеглинки збирають в окремий список і прибирають після циклу.

**Бонус 3.** Перед рухом перевіряють, чи є куди рухатися:
```
def ліворуч(подія):
    x1, y1, x2, y2 = полотно.coords(ракетка)
    if x1 > 0:
        полотно.move(ракетка, -20, 0)

def праворуч(подія):
    x1, y1, x2, y2 = полотно.coords(ракетка)
    if x2 < 500:
        полотно.move(ракетка, 20, 0)
```
Ракетка все одно може виїхати на кілька пікселів, якщо крок більший за залишок відстані. Точніший спосіб — рахувати нову позицію й обмежувати її командою `coords`.

**Бонус 4.** Без `update()` вікно **завмре**: усі переміщення відбудуться в пам'яті, але екран не перемалюється й клавіші перестануть діяти, бо саме `update()` віддає програмі час на опрацювання подій. Без паузи гра запрацює з максимальною швидкістю, на яку здатен комп'ютер: м'яч перетне екран за частку секунди, а процесор завантажиться на повну. Обидві команди в циклі анімації потрібні завжди, і саме в такому порядку — спершу `update()`, потім пауза.

Дайте зіграти комусь із родини й запишіть у зошит: який рахунок вони набрали · що виявилося незручним у керуванні · що ви після цього змінили.

**Якщо комп'ютера вдома немає:** намалюйте на клітинках три послідовні кадри своєї гри й підпишіть координати м'яча та ракетки на кожному. Потім повністю запишіть у зошиті головний цикл гри з усіма перевірками.

## 7. Якщо лишився час

**Гра, з якої почалася індустрія.** Pong вийшов у 1972 році й був майже точно тим, що ви написали сьогодні: два прямокутники, квадратик замість м'яча й рахунок угорі. Перший ігровий автомат поставили в барі, і за кілька днів він зламався — від того, що монетоприймач переповнився монетами. Саме з цієї гри почалася вся ігрова індустрія.

**Чому в іграх окремо рахують логіку й малювання.** У нашому циклі ми рухаємо м'яч і одразу перемальовуємо вікно. У великих іграх це розділяють: логіка рахується з постійною частотою, а малювання — так часто, як встигає відеокарта. Інакше гра на швидкому комп'ютері йшла б швидше, ніж на повільному, — і в старих іграх таке справді траплялося.
