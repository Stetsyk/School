## 2. Пояснення (12-15 хв)

### Блок 1. Вікно без полотна

Вікна робить той самий модуль `tkinter`, з якого ми брали полотно. Тільки тепер полотно нам не потрібне.

```
import tkinter

вікно = tkinter.Tk()
вікно.title("Моя перша програма")
вікно.geometry("400x300")

вікно.mainloop()
```

Розберемо. `Tk()` створює саме вікно. `title` задає напис у заголовку. `geometry` задає розмір: спершу ширина, потім висота, через літеру `x`, і обов'язково в лапках.

Новим тут є лише `geometry` — розмір вікна, який раніше визначався розміром полотна. Розмір пишуть рядком у лапках: спершу ширина, потім висота, через літеру `x`.

Рядок `mainloop()` знайомий: він тримає вікно на екрані й чекає на дії користувача.

> 📝 **Створення вікна:**
>
> ```
> import tkinter
> вікно = tkinter.Tk()
> вікно.title("Назва")
> вікно.geometry("400x300")
> вікно.mainloop()
> ```
>
> `mainloop()` пишуть **останнім рядком**. Це цикл очікування дій користувача, без нього вікно одразу зникне.

> ❓ **Що робить `mainloop()`?**
>
> *Очікуємо:* тримає вікно на екрані й чекає на дії користувача.

### Блок 2. Напис

Усе, що ми ставимо у вікно, називають елементами керування. Найпростіший — напис, англійською `Label`.

```
напис = tkinter.Label(вікно, text="Привіт!", font=("Arial", 20))
напис.pack()
```

Створення елемента складається з двох дій, і обидві обов'язкові.

Спершу **створюємо** елемент. У дужках першим іде вікно, у яке його ставимо, далі налаштування: текст, шрифт, колір.

Потім **розміщуємо** його командою `pack()`. Без неї елемент існує, але на екрані його не видно — це найчастіша помилка теми.

`pack()` укладає елементи один під одним, у порядку створення. Цього нам сьогодні досить.

> 📝 **Напис:**
>
> ```
> напис = tkinter.Label(вікно, text="Привіт!", font=("Arial", 20))
> напис.pack()
> ```
>
> Створення й розміщення — **дві окремі дії**. Без `pack()` елемент не з'явиться на екрані.

> ❓ **Елемент створено, а на екрані його немає. Що забули?**
>
> *Очікуємо:* команду `pack()`.

### Блок 3. Кнопка й обробник події

Тепер найцікавіше. Кнопка створюється так само, але має додаткове налаштування — `command`, тобто що робити при натисканні.

```
def привітатися():
    print("Кнопку натиснуто!")

кнопка = tkinter.Button(вікно, text="Натисни мене", command=привітатися)
кнопка.pack()
```

Функція, яку викликає кнопка, називається **обробником події**. Подія тут — натискання, обробник — наша звичайна функція, точно така сама, як на уроці 20.

І тепер найважливіше правило уроку. У `command` пишуть **ім'я функції без дужок**.

```
command=привітатися        ✅ правильно
command=привітатися()      ❌ неправильно
```

Різниця принципова. Без дужок ми передаємо саму функцію: «ось що виконати, коли натиснуть». З дужками ми виконуємо її **прямо зараз**, і кнопці передається результат — найчастіше `None`. Тоді функція спрацює один раз при запуску, а кнопка не робитиме нічого.

> 📝 **Кнопка й обробник події:**
>
> ```
> кнопка = tkinter.Button(вікно, text="Натисни", command=моя_функція)
> ```
>
> **Ім'я функції пишуть без дужок.** З дужками вона виконається одразу при запуску, а кнопка працювати не буде.

> ❓ **Чому в `command` не можна писати дужки після імені функції?**
>
> *Очікуємо:* тоді функція виконається одразу, а кнопка лишиться порожньою.

### Блок 4. Зміна напису

Виводити в чорне вікно через `print` — не те, чого ми хотіли. Результат має з'являтися у вікні.

Для цього напис змінюють методом `config`:

```
def привітатися():
    напис.config(text="Кнопку натиснуто!")
```

Тепер натискання змінює текст прямо у вікні.

На цьому будується лічильник — той самий, що на уроці 4, але вже з кнопкою:

```
кліків = 0

def клацнути():
    global кліків
    кліків += 1
    напис.config(text=f"Натиснуто разів: {кліків}")
```

Слово `global` тут потрібне тому, що функція змінює змінну, яка живе поза нею. Пам'ятаєте правило з уроку 20: усередині функції своє життя. `global` каже: «ця змінна не своя, а зовнішня».

Користуватися `global` часто не варто — це та сама небезпека, про яку ми говорили. Але для маленької віконної програми це найпростіший спосіб.

> 📝 **Зміна напису:** `напис.config(text="новий текст")`
> Якщо функція змінює зовнішню змінну, на початку функції пишуть `global імя_змінної`.

> ❓ **Навіщо у функції-лічильнику слово `global`?**
>
> *Очікуємо:* щоб функція змінювала зовнішню змінну, а не заводила власну.


### Блок 5. Поле введення

Поле створюється так само, як напис і кнопка, і теж вимагає `pack()`.

```
поле = tkinter.Entry(вікно, font=("Arial", 14), width=10)
поле.pack()
```

`Entry` англійською — «запис». Налаштування `width` задає ширину поля в символах.

Щоб дізнатися, що вписав користувач, є метод `get()`:

```
def показати():
    текст = поле.get()
    напис.config(text=f"Ви ввели: {текст}")
```

І одразу головна пастка: **`get()` завжди повертає текст**. Так само, як `input`. Для обчислень значення треба перетворити:

```
число = int(поле.get())
```

> 📝 **Поле введення:**
>
> ```
> поле = tkinter.Entry(вікно, width=10)
> поле.pack()
> ```
>
> `поле.get()` повертає введене — **завжди як текст**. Для обчислень потрібне `int()` або `float()`.

> ❓ **У поле вписали 5 і 3, а програма вивела 53. У чому помилка?**
>
> *Очікуємо:* забули перетворити текст у числа, і рядки склеїлися.

### Блок 6. Вікна повідомлень

Показувати помилку в написі не завжди зручно — її можна не помітити. Для важливих повідомлень є окремі вікна, вони в підмодулі `messagebox`.

```
from tkinter import messagebox

messagebox.showinfo("Готово", "Обчислення завершено")
messagebox.showwarning("Увага", "Поле порожнє")
messagebox.showerror("Помилка", "Введіть число, а не текст")
```

У всіх трьох перший аргумент — заголовок віконця, другий — сам текст. Різниця лише у значку: інформація, попередження чи помилка.

Такі вікна зупиняють програму, поки користувач не натисне «ОК». Саме тому ними користуються для того, що не можна пропустити.

> 📝 **Вікна повідомлень:**
> `messagebox.showinfo(заголовок, текст)` — інформація
> `messagebox.showwarning(...)` — попередження
> `messagebox.showerror(...)` — помилка
> Підключаються рядком `from tkinter import messagebox`.

> ❓ **Коли краще взяти вікно повідомлення, а не напис?**
>
> *Очікуємо:* коли повідомлення важливе й користувач не повинен його пропустити.

### Блок 7. Захист від порожнього поля

Тепер зберемо все разом. Обробник кнопки має не просто рахувати, а спершу перевірити, чи є з чим працювати.

```
def порахувати():
    a = поле1.get()
    b = поле2.get()
    if a == "" or b == "":
        messagebox.showwarning("Увага", "Заповніть обидва поля")
        return
    if not a.isdigit() or not b.isdigit():
        messagebox.showerror("Помилка", "Введіть числа")
        return
    результат = int(a) + int(b)
    напис.config(text=f"Результат: {результат}")
```

Зверніть увагу на прийом: після повідомлення про помилку стоїть `return`. Він завершує функцію, і подальші обчислення не виконуються. Це те саме раннє повернення, про яке ми говорили на уроці 21.

Порожнє поле впізнають порівнянням із порожніми лапками, а метод `isdigit()` з уроку 18 перевіряє, чи справді введено число.

І окремо про ділення на нуль — його перевіряють до самої дії:

```
if b == 0:
    messagebox.showerror("Помилка", "На нуль ділити не можна")
    return
```

> 📝 **Порядок обробника:** зчитати → перевірити → обчислити → показати.
> Порожнє поле: `if поле.get() == "":`
> Після повідомлення про помилку ставлять `return`, щоб функція далі не працювала.

> ❓ **Навіщо після `showerror` писати `return`?**
>
> *Очікуємо:* щоб функція зупинилась і не рахувала далі з поганими даними.

#### ✅ Відповіді до бонусів

**Бонус 1.**
```
import tkinter
import random

поради = ["Відпочинь", "Спробуй ще раз", "Ти впораєшся", "Зроби перерву"]

def порада():
    напис.config(text=random.choice(поради))
```
Головна ідея: усередині обробника працює будь-який код, зокрема `random` з уроку 22.

**Бонус 2.** обидві працюватимуть однаково, викликаючи ту саму функцію. Це нормально й навіть корисно: наприклад, пункт меню й кнопка на панелі роблять те саме. Помилки тут немає — навпаки, це головна вигода від того, що обробник є звичайною функцією.

**Бонус 3.** Не спрацює тому, що присвоювання всередині функції створює **власну** змінну, а зовнішню не чіпає, і Python скаже, що змінна ще не має значення. Треба попередити його словом `global`:
```
лічильник = 0

def натиснули():
    global лічильник
    лічильник += 1
    напис.config(text=f"Натискань: {лічильник}")
```
Слово `global` означає «працюй із зовнішньою змінною, а не заводь нову». У великих програмах його намагаються уникати, але для маленького віконця це найпростіше рішення.

**Бонус 4.** Без дужок ви передаєте кнопці **саму функцію**, і вона викличе її при натисканні. З дужками Python викликає функцію **одразу**, у момент створення кнопки, а кнопці передає її результат, тобто зазвичай `None`. Ознака цієї помилки характерна: привітання з'являється відразу після запуску програми, а натискання кнопки потім не робить нічого. Правило просте: у `command` ім'я функції пишуть **без дужок**.

**Бонус 5.** замість `int` узяти `float`, а перевірку `isdigit()` замінити, бо для `"2.5"` вона дає `False`. Найпростіший надійний спосіб:
```
try:
    a = float(поле1.get())
except ValueError:
    messagebox.showerror("Помилка", "Введіть число")
    return
```
Конструкція `try` — «спробуй, а якщо не вийде, зроби ось це». Її ми в курсі не вивчали, але саме так у справжніх програмах перевіряють введення.

**Бонус 6.**
```
вікно.bind("<Return>", лямбда_обробник)
```
Метод `bind` прив'язує будь-яку клавішу до обробника. Правда, обробник для `bind` має приймати один додатковий параметр — відомості про подію:
```
def порахувати_клавішею(подія):
    порахувати()

вікно.bind("<Return>", порахувати_клавішею)
```

**Бонус 7.** `.isdigit()` вважає числом лише рядок із самих цифр, тому він відкине і від'ємні числа, і дробові.
```
текст = поле.get().strip().replace(",", ".")
try:
    число = float(текст)
except ValueError:
    messagebox.showerror("Помилка", "Введіть число")
    return
```
Конструкція `try` пробує виконати перетворення, а `except` спрацьовує, тільки якщо воно не вдалося. Це надійний спосіб перевірки будь-якого введення, і саме його використовують у справжніх програмах.

**Бонус 8.** Поле очищають одним рядком: `поле.delete(0, "end")`. Показувати результат краще в написі, бо вікно повідомлення доводиться щоразу закривати кнопкою, а це зайва дія на кожне обчислення. Крім того, напис лишається на екрані, і попередній результат видно, поки набираєш наступний. Вікна повідомлень залишають для того, для чого вони придумані, — для помилок і попереджень.

## 7. Якщо лишився час

**Звідки взялися вікна.** Перший комп'ютер із вікнами, мишею й кнопками створили в дослідницькому центрі Xerox у 1973 році. Компанія не побачила в цьому комерційної перспективи. У 1979-му лабораторію відвідав молодий Стів Джобс, і побачене стало основою для Apple Macintosh, а згодом і для Windows. Ідею, яка змінила світ, її автори просто не оцінили.

**Що таке подієве програмування.** Усі наші попередні програми виконувались згори вниз і закінчувались. Віконна програма влаштована інакше: вона запускається й **чекає**. Далі все, що відбувається, — це реакція на події: натискання, рух миші, введення тексту. Такий підхід називають подієвим, і за ним працюють усі сучасні застосунки, від браузера до гри.

**Скільки коштує неперевірене поле.** Величезна частина зламаних сайтів у світі постраждала через те, що програма повірила введеному в поле. Користувач вписував не те, чого чекали автори, і програма робила щось непередбачене. Тому в професійній розробці діє залізне правило: усе, що прийшло від користувача, вважається ворожим, поки не перевірене.

**Правило захисту від дурня.** Англійською цей принцип називають захистом від помилкового використання, і формулюють так: програма має правильно поводитися при будь-якому введенні, а не лише при очікуваному. Перевірити це просто: дайте свою програму людині, яка її не писала, і попросіть зламати. Ви здивуєтесь, скільки способів вона знайде за дві хвилини.
