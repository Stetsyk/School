Так само працює лічильник переглядів під відео. Так само працює рахунок у грі. Так само працює кількість непрочитаних повідомлень.

## 2. Пояснення (12-15 хв)

### Блок 1. Старе значення зникає назавжди

Змінній можна присвоювати значення скільки завгодно разів. Але щоразу старе значення **затирається** — повернути його вже не можна.

```
оцінка = 7
оцінка = 10
print(оцінка)     → 10
```

Сімки в програмі більше не існує. Коробка одна, і в ній лежить те, що поклали останнім.

> 📝 Змінній можна присвоїти нове значення в будь-який момент. **Старе значення при цьому зникає назавжди.**

> ❓ **Після трьох рядків `n = 1`, `n = 5`, `n = 9` що виведе `print(n)`?**
>
> *Очікуємо:* 9. Два попередні значення затерті.

### Блок 2. Трасування: як стежити за програмою

Коли програма не працює, програміст робить одне: бере аркуш і виписує, що лежить у кожній змінній після кожного рядка. Це називається трасуванням, і це найкорисніша навичка курсу.

Розберемо разом:

```
a = 3
b = 5
a = a + b
b = b - a
```

| Рядок | a | b |
| :---: | :---: | :---: |
| 1 | 3 | — |
| 2 | 3 | 5 |
| 3 | 8 | 5 |
| 4 | 8 | −3 |

Головне правило: у рядку 4 береться **нове** значення `a`, тобто 8, а не початкове 3. Комп'ютер завжди працює з тим, що лежить у змінній зараз.

> 📝 **Трасування** — покроковий запис того, що лежить у кожній змінній після кожного рядка програми. Так шукають помилки.
> У кожному рядку беруться **поточні** значення змінних, а не початкові.

> ❓ **У програмі `x = 2`, `x = x * 3`, `y = x + 1` — що буде в `y`?**
>
> *Очікуємо:* 7. До моменту третього рядка в `x` уже лежить 6.

### Блок 3. Лічильник і накопичувач

Два прийоми, які трапляються в програмах постійно.

**Лічильник** рахує кількість. Починається з нуля і щоразу збільшується на одиницю.

```
кроків = 0
кроків = кроків + 1
кроків = кроків + 1
print(кроків)     → 2
```

**Накопичувач** збирає суму. Теж починається з нуля, але додає щоразу різне.

```
сума = 0
сума = сума + 250     # перша покупка
сума = сума + 130     # друга покупка
print(сума)           → 380
```

Різниця лише в тому, що додається: лічильник завжди додає одиницю, накопичувач — чергове значення. І в обох випадках **починати треба з нуля**, інакше додавати буде нікуди.

> 📝 **Лічильник** — змінна, яка рахує кількість: `лічильник = лічильник + 1`
> **Накопичувач** — змінна, яка збирає суму: `сума = сума + значення`
> Обидва спочатку обнуляють: `= 0`.

> ❓ **Чому лічильник обов'язково обнуляти перед першим використанням?**
>
> *Очікуємо:* до порожньої змінної не можна нічого додати, Python видасть помилку.

### Блок 4. Скорочений запис

Рядок `сума = сума + 250` пишуть так часто, що для нього придумали коротку форму.

```
сума += 250      # те саме, що сума = сума + 250
кроків += 1      # те саме, що кроків = кроків + 1
баланс -= 50     # те саме, що баланс = баланс - 50
ціна *= 2        # те саме, що ціна = ціна * 2
```

Працює однаково, читається швидше. Далі в курсі будемо користуватися саме таким записом.

> 📝 **Скорочені оператори:**
>
> | Скорочено | Повністю |
> | :---: | --- |
> | `a += 5` | `a = a + 5` |
> | `a -= 5` | `a = a - 5` |
> | `a *= 5` | `a = a * 5` |
> | `a /= 5` | `a = a / 5` |

> ❓ **У змінній `бал` лежить 8. Що буде після рядка `бал += 4`?**
>
> *Очікуємо:* 12.


### Блок 5. Обмін значень

Спробуємо наївний спосіб і простежимо його по кроках.

```
a = 3
b = 8
a = b      # тепер a = 8, а трійка зникла назавжди
b = a      # у a лежить 8, тому b теж стає 8
```

Результат: `a = 8`, `b = 8`. Трійки в програмі більше немає — її затерли в третьому рядку.

Правильний спосіб — рівно як зі склянками. Потрібна третя змінна, куди відкладаємо значення на час.

```
c = a      # відклали 3 в запасну змінну
a = b      # a стало 8
b = c      # b взяло 3 із запасної
```

> 📝 **Обмін значень двох змінних** виконується через третю:
> `c = a` · `a = b` · `b = c`
> Без третьої змінної одне зі значень затирається й губиться.

> ❓ **Чому не можна поміняти значення двома рядками `a = b` і `b = a`?**
>
> *Очікуємо:* після першого рядка старе значення `a` вже стерте, і в обох змінних опиняється те саме число.

### Блок 6. Задача в кілька кроків

Коли задача складніша за один вираз, її розв'язують по кроках, і кожен проміжний результат кладуть в окрему змінну з осмисленим іменем.

Приклад: скільки коштує пофарбувати кімнату, якщо стіни 4 на 3 метри, висота 2.5 метра, а фарби треба 0.2 літра на квадратний метр при ціні 180 грн за літр?

```
довжина = 4
ширина = 3
висота = 2.5
периметр = 2 * (довжина + ширина)
площа_стін = периметр * висота
літрів = площа_стін * 0.2
вартість = літрів * 180
print("Треба заплатити:", вартість)
```

Можна було втиснути все в один довгий рядок. Але тоді помилку в ньому не знайти, а так кожен крок видно окремо і його легко перевірити.

> 📝 **Правило багатокрокової задачі:** кожен проміжний результат — в окрему змінну з осмисленим іменем. Так помилку видно одразу, а програму легко читати.

> ❓ **Навіщо розбивати обчислення на кілька рядків, якщо все можна записати одним виразом?**
>
> *Очікуємо:* щоб бачити проміжні результати й швидко знаходити, на якому кроці помилка.

## 3. Перевірка розуміння (4-6 хв)

**Бонус 1.** Що виведе ця програма і чому відповідь не 0?

**Бонус 4.** Накопичувач суми починають з нуля. З якого числа треба починати накопичувач **добутку** і що станеться, якщо теж узяти нуль?

a, b = b, a

Перевірте, що це працює, і поясніть словами, чому третя змінна тут не потрібна.

**Бонус 6.** Поміняйте місцями значення **трьох** змінних по колу: щоб у `a` опинилося те, що було в `b`, у `b` те, що було в `c`, а в `c` те, що було в `a`. Скільки допоміжних змінних потрібно?

**Бонус 8.** Обміняйте значення двох чисел **без** третьої змінної, користуючись лише додаванням і відніманням.

#### ✅ Відповіді до бонусів

**Бонус 1.** 5. У рядку 2 в `b` потрапила **копія** значення, а не зв'язок зі змінною `a`. Подальша зміна `a` на `b` не впливає.

**Бонус 2.** помилку `NameError`, бо змінної `кроків` не існує. Щоб додати одиницю, треба спершу мати до чого додавати. Це найчастіша помилка при роботі з лічильниками.

**Бонус 3.** 2 → 4 → 8 → 5 → 2. Останній рядок ділить націло, тому 5 // 2 дає 2, а не 2.5.

**Бонус 4.** З одиниці. Нуль, помножений на будь-що, дає нуль, тому добуток так і залишиться нулем до самого кінця, скільки б чисел ви не перемножили. Загальне правило: початкове значення накопичувача — це число, яке **не змінює результат** дії. Для додавання це 0, для множення 1.

**Бонус 5.** Python спершу обчислює всю праву частину й запам'ятовує обидва значення, а вже потім розкладає їх по змінних. Тобто запасне місце все одно є, просто його створює сама мова, а не ми.

**Бонус 6.** одна.
```
t = a
a = b
b = c
c = t
```

**Бонус 7.** Одна.
```
тимч = a
a = b
b = c
c = тимч
```
Ідея та сама, що при обміні двох: зберігаємо те значення, яке буде затерте найпершим, і повертаємо його в кінці ланцюжка.

**Бонус 8.**
```
a = a + b
b = a - b
a = a - b
```
Після першого рядка в `a` лежить сума обох чисел. Другий дістає з неї старе `a` й кладе в `b`. Третій дістає старе `b`. Спосіб працює тільки для чисел, і в справжніх програмах його не використовують: він коротший, зате незрозумілий тому, хто читатиме код.

## 7. Якщо лишився час

**Найвідоміший лічильник у світі.** У 2014 році відео «Gangnam Style» зламало лічильник переглядів YouTube. Під нього була відведена комірка, у якій поміщалося трохи більше двох мільярдів — і цього здавалося достатньо назавжди. Коли число перевищило межу, лічильник почав показувати від'ємні значення. Інженерам довелося терміново збільшувати комірку.

**Лічильники в іграх.** Кількість патронів, монет, життів, рівень персонажа — усе це звичайні змінні з `+=` і `-=`. Коли ви бачите в грі число, яке росте, за ним стоїть рівно той рядок, який ми сьогодні писали. Різниця тільки в тому, що там таких змінних кілька тисяч.

**Чому обмін значень питають на співбесідах.** Задача виглядає дитячою, але показує одразу дві речі: чи розуміє людина, що присвоювання затирає старе значення, і чи вміє вона перевірити своє рішення по кроках, а не вгадати. Якщо кандидат одразу пише через третю змінну й пояснює чому — далі можна говорити про серйозніші речі.

**Обмін без третьої змінної.** Для чисел існує хитрий спосіб: `a = a + b`, потім `b = a - b`, потім `a = a - b`. Перевірте на папері — працює. Колись так економили пам'ять, коли її було по кілька кілобайтів. Сьогодні так не пишуть: код заплутаний, а економія жодна.
