## 1. Вступ-гачок (2-3 хв)

За чотири уроки ми навчилися всьому, що потрібно для першої справжньої програми з логікою. Подивіться, що вже вміємо: питати, порівнювати, вибирати з двох варіантів, вибирати з багатьох, з'єднувати умови через «і» та «або».

Цього достатньо, щоб написати те, чим ви користуєтесь щодня: онлайн-тест.

Будь-який тест влаштований однаково. Питання. Відповідь. Перевірка. Плюс бал, якщо правильно. І в кінці — оцінка за шкалою. Усе це ми вже знаємо: перевірка — це `if`, бал — це накопичувач з уроку 5, шкала — це ланцюжок `elif` з минулого уроку.

Сьогодні складаємо все докупи. Наприкінці уроку у вас буде тест, який можна дати пройти однокласнику.

## 2. Пояснення (6-8 хв)

### Блок 1. Накопичувач балів

Тест — це та сама змінна-лічильник, яку ми робили на уроці 5, тільки збільшується вона не завжди, а за умовою.

```
бали = 0

відповідь = input("Столиця України? ")
if відповідь == "Київ":
    бали += 1

відповідь = input("Скільки днів у тижні? ")
if відповідь == "7":
    бали += 1

print(f"Ваш результат: {бали} з 2")
```

Три речі варто помітити. Змінна `бали` обнуляється **до** всіх питань. Одна й та сама змінна `відповідь` використовується повторно — попередня відповідь уже не потрібна. І відповідь порівнюється як текст, тому сімка теж у лапках.

> 📝 **Схема тесту:** обнулити лічильник балів → питання → перевірка через `if` → `бали += 1` за правильну відповідь → підсумок.
> Лічильник обнуляють **один раз на початку**, до всіх питань.

> ❓ **Що станеться, якщо написати `бали = 0` перед кожним питанням?**
>
> *Очікуємо:* лічильник щоразу скидатиметься, і в кінці буде максимум один бал.

### Блок 2. Шкала оцінювання

Коли бали пораховані, залишається перевести їх в оцінку. Це ланцюжок `elif` з минулого уроку.

```
if бали == 5:
    print("Відмінно! Усе правильно")
elif бали >= 3:
    print("Добре, але є над чим попрацювати")
else:
    print("Варто повторити тему")
```

Умови, як домовлялися, від найвужчої до найширшої.

> 📝 **Шкала результату** будується ланцюжком `if-elif-else` за кількістю балів, від найвищого результату до найнижчого.

> ❓ **Чому гілку `бали >= 3` не можна поставити першою?**
>
> *Очікуємо:* вона істинна й для п'яти балів, тому найкращий результат ніколи не з'явиться.

### Блок 3. Дрібниці, які роблять програму дорослою

Три речі, які відрізняють хорошу програму від просто працюючої.

**Порівняння без урахування регістру.** Учень напише `київ` з малої, і програма зарахує помилку. Виправляється методом `.lower()`, який переводить введене в малі літери:

```
if відповідь.lower() == "київ":
```

**Захист від ділення на нуль.** Якщо десь ділите — перевірте дільник:

```
if кількість == 0:
    print("Немає питань")
else:
    print(бали / кількість * 100)
```

**Відсоток правильних.** Просте обчислення, яке робить результат зрозумілішим: `бали / 5 * 100`.

> 📝 **Метод `.lower()`** переводить текст у малі літери. Використовують при порівнянні відповідей, щоб регістр не впливав: `if відповідь.lower() == "київ":`
> Перед діленням завжди перевіряють, чи дільник не нуль.

> ❓ **Навіщо потрібен `.lower()` у перевірці відповіді?**
>
> *Очікуємо:* щоб `Київ`, `київ` і `КИЇВ` зараховувались однаково.

## 3. Перевірка розуміння (3-5 хв)

1. **Де в програмі-тесті обнуляють лічильник балів?**
   Один раз на самому початку, до всіх питань.

2. **Як додати бал за правильну відповідь?**
   `бали += 1` усередині `if`.

3. **Чим будують шкалу результату?**
   Ланцюжком `if-elif-else`.

4. **Що робить `.lower()`?**
   Переводить текст у малі літери, щоб регістр не впливав на порівняння.

5. **Що треба перевірити перед діленням?**
   Що дільник не дорівнює нулю.

## 5. ⭐ Бонус для сильних

**Бонус 1.** Додайте до тесту питання з варіантами відповіді А, Б, В. Користувач вводить літеру, а програма зараховує правильну незалежно від регістру й зайвих пробілів.

**Бонус 2.** Зробіть так, щоб тест зараховував відповідь `Київ` і `Киев`, а також `7` і `сім`.

**Бонус 3.** Додайте до тесту виведення результату у відсотках із одним знаком після коми. Питань п'ять.

**Бонус 4.** Зробіть так, щоб тест зараховував відповідь `Київ`, `київ`, `КИЇВ` і навіть ` київ ` з пробілами. Одного `.lower()` тут замало.

#### ✅ Відповіді до бонусів

**Бонус 1.** `if відповідь.strip().lower() == "б":`. Метод `strip` прибирає пробіли по краях, `lower` переводить у малі літери. Обидва можна застосовувати підряд.

**Бонус 2.** через `or` з кількома варіантами:
```
if відповідь.lower() == "київ" or відповідь.lower() == "киев":
```
Коротший спосіб через список ми вивчимо на уроці 25: `if відповідь.lower() in ["київ", "киев"]:`

**Бонус 3.** Відсоток — це частка правильних, помножена на 100: `print(f"Результат: {бали / 5 * 100:.1f}%")`. Для трьох правильних вийде `60.0%`. Ділити треба саме на кількість питань, а не на 5 числом: якщо ви колись додасте шосте питання, формулу з числом доведеться шукати й правити, тому кількість краще тримати в змінній.

**Бонус 4.** Потрібні два методи підряд: `.strip()` прибирає пробіли з країв, `.lower()` переводить у малі літери.
```
відповідь = input("Столиця України? ").strip().lower()
if відповідь == "київ":
    бали += 1
```
Порядок тут не важливий, але зразок для порівняння теж має бути з малих літер. Це та дрібниця, через яку учні найчастіше отримують нуль за правильну відповідь.

## 7. Якщо лишився час

**Скільки коштує неправильна перевірка відповіді.** У великих онлайн-тестах відповідь порівнюють не просто через рівність: враховують зайві пробіли, різні лапки, кириличну й латинську літеру «і», регістр. Один із найвідоміших випадків — коли тисячі учнів отримали нуль за правильну відповідь лише тому, що набрали її з великої літери. Саме через це ми додали `.lower()`.

**Чому питання в тестах перемішують.** Якщо всі проходять тест в однаковому порядку, відповіді швидко розходяться по класу. Тому в справжніх системах питання й варіанти щоразу перемішують випадковим чином. Ми навчимося це робити на уроці 35, коли з'явиться модуль `random`.
