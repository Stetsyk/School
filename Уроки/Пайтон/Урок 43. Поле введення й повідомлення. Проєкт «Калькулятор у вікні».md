## 2. Пояснення (7-9 хв)

### Блок 1. Поле введення

Поле створюється так само, як напис і кнопка, і теж вимагає `pack()`.

```
поле = tkinter.Entry(вікно, font=("Arial", 14), width=10)
поле.pack()
```

`Entry` англійською — «запис». Налаштування `width` задає ширину поля в символах.

Щоб дізнатися, що вписав користувач, є метод `get()`:

```
def показати():
    текст = поле.get()
    напис.config(text=f"Ви ввели: {текст}")
```

І одразу головна пастка: **`get()` завжди повертає текст**. Так само, як `input`. Для обчислень значення треба перетворити:

```
число = int(поле.get())
```

> 📝 **Поле введення:**
>
> ```
> поле = tkinter.Entry(вікно, width=10)
> поле.pack()
> ```
>
> `поле.get()` повертає введене — **завжди як текст**. Для обчислень потрібне `int()` або `float()`.

> ❓ **У поле вписали 5 і 3, а програма вивела 53. У чому помилка?**
>
> *Очікуємо:* забули перетворити текст у числа, і рядки склеїлися.

### Блок 2. Вікна повідомлень

Показувати помилку в написі не завжди зручно — її можна не помітити. Для важливих повідомлень є окремі вікна, вони в підмодулі `messagebox`.

```
from tkinter import messagebox

messagebox.showinfo("Готово", "Обчислення завершено")
messagebox.showwarning("Увага", "Поле порожнє")
messagebox.showerror("Помилка", "Введіть число, а не текст")
```

У всіх трьох перший аргумент — заголовок віконця, другий — сам текст. Різниця лише у значку: інформація, попередження чи помилка.

Такі вікна зупиняють програму, поки користувач не натисне «ОК». Саме тому ними користуються для того, що не можна пропустити.

> 📝 **Вікна повідомлень:**
> `messagebox.showinfo(заголовок, текст)` — інформація
> `messagebox.showwarning(...)` — попередження
> `messagebox.showerror(...)` — помилка
> Підключаються рядком `from tkinter import messagebox`.

> ❓ **Коли краще взяти вікно повідомлення, а не напис?**
>
> *Очікуємо:* коли повідомлення важливе й користувач не повинен його пропустити.

### Блок 3. Захист від порожнього поля

Тепер зберемо все разом. Обробник кнопки має не просто рахувати, а спершу перевірити, чи є з чим працювати.

```
def порахувати():
    a = поле1.get()
    b = поле2.get()
    if a == "" or b == "":
        messagebox.showwarning("Увага", "Заповніть обидва поля")
        return
    if not a.isdigit() or not b.isdigit():
        messagebox.showerror("Помилка", "Введіть числа")
        return
    результат = int(a) + int(b)
    напис.config(text=f"Результат: {результат}")
```

Зверніть увагу на прийом: після повідомлення про помилку стоїть `return`. Він завершує функцію, і подальші обчислення не виконуються. Це те саме раннє повернення, про яке ми говорили на уроці 33.

Порожнє поле впізнають порівнянням із порожніми лапками, а метод `isdigit()` з уроку 29 перевіряє, чи справді введено число.

І окремо про ділення на нуль — його перевіряють до самої дії:

```
if b == 0:
    messagebox.showerror("Помилка", "На нуль ділити не можна")
    return
```

> 📝 **Порядок обробника:** зчитати → перевірити → обчислити → показати.
> Порожнє поле: `if поле.get() == "":`
> Після повідомлення про помилку ставлять `return`, щоб функція далі не працювала.

> ❓ **Навіщо після `showerror` писати `return`?**
>
> *Очікуємо:* щоб функція зупинилась і не рахувала далі з поганими даними.

#### ✅ Відповіді до бонусів

**Бонус 1.** замість `int` узяти `float`, а перевірку `isdigit()` замінити, бо для `"2.5"` вона дає `False`. Найпростіший надійний спосіб:
```
try:
    a = float(поле1.get())
except ValueError:
    messagebox.showerror("Помилка", "Введіть число")
    return
```
Конструкція `try` — «спробуй, а якщо не вийде, зроби ось це». Її ми в курсі не вивчали, але саме так у справжніх програмах перевіряють введення.

**Бонус 2.**
```
вікно.bind("<Return>", лямбда_обробник)
```
Метод `bind` прив'язує будь-яку клавішу до обробника. Правда, обробник для `bind` має приймати один додатковий параметр — відомості про подію:
```
def порахувати_клавішею(подія):
    порахувати()

вікно.bind("<Return>", порахувати_клавішею)
```

**Бонус 3.** `.isdigit()` вважає числом лише рядок із самих цифр, тому він відкине і від'ємні числа, і дробові.
```
текст = поле.get().strip().replace(",", ".")
try:
    число = float(текст)
except ValueError:
    messagebox.showerror("Помилка", "Введіть число")
    return
```
Конструкція `try` пробує виконати перетворення, а `except` спрацьовує, тільки якщо воно не вдалося. Це надійний спосіб перевірки будь-якого введення, і саме його використовують у справжніх програмах.

**Бонус 4.** Поле очищають одним рядком: `поле.delete(0, "end")`. Показувати результат краще в написі, бо вікно повідомлення доводиться щоразу закривати кнопкою, а це зайва дія на кожне обчислення. Крім того, напис лишається на екрані, і попередній результат видно, поки набираєш наступний. Вікна повідомлень залишають для того, для чого вони придумані, — для помилок і попереджень.

## 7. Якщо лишився час

**Скільки коштує неперевірене поле.** Величезна частина зламаних сайтів у світі постраждала через те, що програма повірила введеному в поле. Користувач вписував не те, чого чекали автори, і програма робила щось непередбачене. Тому в професійній розробці діє залізне правило: усе, що прийшло від користувача, вважається ворожим, поки не перевірене.

**Правило захисту від дурня.** Англійською цей принцип називають захистом від помилкового використання, і формулюють так: програма має правильно поводитися при будь-якому введенні, а не лише при очікуваному. Перевірити це просто: дайте свою програму людині, яка її не писала, і попросіть зламати. Ви здивуєтесь, скільки способів вона знайде за дві хвилини.
