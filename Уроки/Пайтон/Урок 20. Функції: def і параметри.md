## 2. Пояснення (12-15 хв)

### Блок 1. Проблема повторів

Подивимось на конкретну програму:

```
print("=" * 30)
print("МЕНЮ")
print("=" * 30)

# ... якісь дії ...

print("=" * 30)
print("РЕЗУЛЬТАТ")
print("=" * 30)
```

Шість рядків, з яких чотири однакові. І це ще маленька програма.

Повтори погані трьома речами. Програма довша, ніж треба. Виправляти доводиться в кількох місцях одразу. І там, де щось повторюється чотири рази, легко помилитися саме в одному.

Правило, яке в програмуванні знають усі: **якщо ви пишете те саме втретє — зупиніться й винесіть це в функцію**.

> 📝 **Повторення однакового коду** робить програму довшою, а зміни доводиться вносити в кількох місцях. Повторюваний код виносять в окрему **функцію**.

> ❓ **Скільки місць доведеться виправити, щоб змінити рамку в програмі з чотирма однаковими рядками?**
>
> *Очікуємо:* усі чотири, і легко пропустити одне.

### Блок 2. Команда def

Функція — це шматок програми, якому дали ім'я. Описується командою `def` від англійського *define*, «визначити».

```
def рамка():
    print("=" * 30)
```

Після `def` іде ім'я функції, потім порожні круглі дужки, двокрапка й тіло з відступом — усе точно так само, як в `if` і `for`.

Тепер функцію можна **викликати** — просто написати її ім'я з дужками:

```
рамка()
print("МЕНЮ")
рамка()
```

Перепишемо той приклад із повторами:

```
def рамка():
    print("=" * 30)

рамка()
print("МЕНЮ")
рамка()

рамка()
print("РЕЗУЛЬТАТ")
рамка()
```

Тепер рамка описана **один раз**. Захотіли змінити — правите одне місце, і зміниться скрізь.

> 📝 **Опис функції:**
>
> ```
> def назва():
>     тіло функції
> ```
>
> **Виклик функції:** `назва()` — обов'язково з дужками.
> Функцію описують один раз, а викликають скільки завгодно.

> ❓ **Що станеться, якщо викликати функцію без дужок, написавши просто `рамка`?**
>
> *Очікуємо:* нічого не виконається, дужки і є командою виконати.

### Блок 3. Опис не виконує

Найважливіше про функції на сьогодні.

**Опис функції нічого не виконує.** Коли Python бачить `def`, він лише запам'ятовує: є така функція, і ось що вона робить. Тіло при цьому не виконується.

```
def привітання():
    print("Привіт!")

print("Програма почалась")
```

Ця програма виведе тільки `Програма почалась`. Слово `Привіт!` не з'явиться, бо функцію ніхто не викликав.

І друге правило, яке з цього випливає: **функція має бути описана раніше, ніж викликана**. Якщо викликати її до опису, Python скаже, що не знає такого імені.

Тому програму зазвичай будують так: спершу всі описи функцій, потім основна частина.

> 📝 **Опис функції її не виконує** — він лише запам'ятовує, що вона робить. Виконується функція тільки при виклику.
> Функція має бути **описана раніше**, ніж викликана. Спершу всі `def`, потім основна частина програми.

> ❓ **Програма містить лише опис функції й жодного виклику. Що вона виведе?**
>
> *Очікуємо:* нічого.

### Блок 4. Імена функцій

Правила ті самі, що для змінних: літери, цифри, підкреслення, не починати з цифри.

Але є важлива домовленість щодо змісту імені. **Функцію називають дієсловом** — за тим, що вона робить: `намалювати_рамку`, `порахувати_середнє`, `показати_меню`. Змінну називають іменником, бо в ній щось лежить: `сума`, `оцінки`, `імя`.

Ще одне: одна функція має робити **одну річ**. Якщо в описі функції довелося написати «і», це, найпевніше, дві функції.

> 📝 **Ім'я функції** — дієслово, за тим, що вона робить: `намалювати_рамку`, `показати_меню`.
> Одна функція робить **одну річ**.

> ❓ **Яке ім'я краще для функції, яка виводить заголовок: `заголовок` чи `показати_заголовок`?**
>
> *Очікуємо:* друге, бо функція щось робить, і це видно з назви.


### Блок 5. Параметр

Параметр — це змінна, яку функція отримує ззовні. Пишеться в тих самих круглих дужках, які досі стояли порожні.

```
def рамка(ширина):
    print("=" * ширина)
```

Тепер при виклику ширину вказують у дужках:

```
рамка(30)
рамка(50)
рамка(10)
```

Одна функція, три різні результати.

Значення, яке передають при виклику, називають **аргументом**. Тобто `ширина` — це параметр в описі, а `30` — аргумент при виклику. Різниця в словах невелика, і на практиці їх часто плутають, нічого страшного.

> 📝 **Параметр** — змінна, яку функція отримує ззовні. Записується в дужках при описі.
>
> ```
> def рамка(ширина):
>     print("=" * ширина)
> ```
>
> **Аргумент** — конкретне значення, яке передають при виклику: `рамка(30)`.

> ❓ **Скільки різних рамок можна отримати від функції `рамка(ширина)`?**
>
> *Очікуємо:* скільки завгодно, залежно від переданого числа.

### Блок 6. Кілька параметрів

Параметрів може бути кілька — тоді їх перелічують через кому.

```
def рамка(символ, ширина):
    print(символ * ширина)

рамка("=", 30)
рамка("*", 50)
рамка("-", 10)
```

**Порядок має значення.** Перший аргумент потрапляє в перший параметр, другий у другий. Якщо переплутати місцями і написати `рамка(30, "=")`, Python спробує помножити число на текст у зворотному порядку і, залежно від дії, або видасть помилку, або зробить не те.

Кількість теж має збігатися: якщо параметрів два, а передали один — буде помилка `TypeError`.

> 📝 **Кілька параметрів** перелічують через кому: `def рамка(символ, ширина):`
> **Порядок аргументів має значення** — перший іде в перший параметр.
> Кількість аргументів має збігатися з кількістю параметрів.

> ❓ **Що станеться при виклику `рамка("=")`, якщо функція описана з двома параметрами?**
>
> *Очікуємо:* помилка, бракує другого аргументу.

### Блок 7. Параметр живе тільки всередині

Параметр — звичайна змінна, але існує вона **тільки в тілі функції**. Зовні її не видно.

```
def вітання(імя):
    print(f"Привіт, {імя}!")

вітання("Оля")
print(імя)        → NameError, такої змінної немає
```

Це не обмеження, а зручність. Завдяки цьому в різних функціях можна спокійно брати однакові імена параметрів і не боятися, що вони переплутаються.

І навпаки: те, що змінна називається так само зовні, нічого не означає — функція працює зі своєю копією.

```
імя = "Іван"

def вітання(імя):
    імя = "Оля"
    print(імя)

вітання("Марія")     → Оля
print(імя)          → Іван
```

> 📝 **Параметр існує тільки всередині функції.** Зовні його не видно, і зміни всередині не впливають на зовнішні змінні з таким самим іменем.

> ❓ **Чи можна звернутися до параметра після того, як функція відпрацювала?**
>
> *Очікуємо:* ні, він існує лише в тілі функції.

### Блок 8. Функція друкує, а не повертає

Поки що всі наші функції щось **виводять** на екран. Це важлива обмеженість, і її варто помітити зараз.

```
def вартість(ціна, кількість):
    print(ціна * кількість)

вартість(5, 4)              → 20 на екрані
```

Функція справді порахувала. Але результат одразу пішов на екран — і використати його далі не вийде:

```
дві_покупки = вартість(5, 4) * 2      → не працює як очікується
```

Функція, яка друкує, годиться для оформлення: рамки, заголовки, меню, повідомлення. Для обчислень потрібно вміти **повертати** результат, а не друкувати — про це буде наступний урок.

> 📝 Функція, яка друкує результат, годиться для **оформлення**. Для обчислень результат треба **повертати** — це тема наступного уроку.

> ❓ **Чому результат функції, яка друкує, не можна використати в подальших обчисленнях?**
>
> *Очікуємо:* він пішов на екран, а не у програму, зберегти його ніде.

#### ✅ Відповіді до бонусів

**Бонус 1.** може, і це роблять постійно.
```
def лінія():
    print("-" * 20)

def заголовок():
    лінія()
    print("МОЯ ПРОГРАМА")
    лінія()

заголовок()
```
Головна ідея: з простих функцій складають складніші, як із цеглинок. Саме так будують великі програми.

**Бонус 2.** програма зупиниться з помилкою `RecursionError` приблизно після тисячі кроків. Виклик функції самої себе називається рекурсією, він буває дуже корисним, але потребує умови зупинки — інакше виходить те саме, що з нескінченним циклом.

**Бонус 3.** Тільки слово `Початок`. Команда `def` лише **описує** функцію й запам'ятовує її, але не виконує. Щоб привітання з'явилося, потрібен виклик `привітати()` окремим рядком. Описана й жодного разу не викликана функція — звична причина того, що «програма нічого не робить», і помилки при цьому немає.

**Бонус 4.** Ні, буде помилка `NameError`. Python читає програму згори вниз, і на момент виклику він ще не знає такого імені. Тому всі описи функцій ставлять **на початку** файлу, а виклики — після них. Виняток лише один: усередині однієї функції можна викликати іншу, описану нижче, бо тіло виконується не тоді, коли читається, а тоді, коли функцію викликали.

**Бонус 5.**
```
def показати(список):
    for i in range(len(список)):
        print(f"{i + 1}. {список[i]}")

показати(["Київ", "Львів", "Одеса"])
```
Головна ідея: параметром може бути не лише число чи текст, а й цілий список.

**Бонус 6.** `[1, 2, 3, 100]`. Здавалося б, функція працює з копією, але зі списками це не так: у параметр потрапляє не копія списку, а те саме ім'я. Тому зміни всередині функції видно й зовні. Для чисел і рядків так не буває. Якщо змінювати список не треба, у функцію передають його копію: `додати(числа[:])`.

**Бонус 7.** `7` і `-7`. Значення потрапляють у параметри **за порядком**: перше число стає `a`, друге `b`. Тому переставлені аргументи дають інший результат, хоч виклик виглядає майже однаково. У Python є спосіб убезпечитися — називати аргументи явно: `різниця(b=3, a=10)` дасть 7 незалежно від порядку.

**Бонус 8.** Обидва дадуть помилку `TypeError`: Python вимагає **точно стільки** аргументів, скільки параметрів у описі. Щоб дозволити виклик з одним числом, параметру дають значення за замовчуванням: `def різниця(a, b=0):`. Тоді `різниця(10)` спрацює й дасть 10, а `різниця(10, 3)` — 7. Параметри зі значеннями за замовчуванням завжди ставлять **останніми** в описі.

## 7. Якщо лишився час

**Скільки функцій у справжній програмі.** У великій програмі їх тисячі, і жодна не має бути довшою за екран. Є навіть неписане правило: якщо функція не поміщається на одному екрані, її час розбивати. Причина проста — довгу функцію неможливо втримати в голові цілком, а отже, неможливо впевнено змінити.

**Правило трьох.** Професійна домовленість звучить так: перший раз пиши як є, другий раз потерпи, третій раз — виноси у функцію. Раніше виносити теж не варто: буває, що два схожі шматки з часом розходяться, і спільна функція починає заважати.

**Скільки параметрів забагато.** Загальна домовленість: більше чотирьох параметрів — привід задуматися. При п'яти й більше майже неможливо не переплутати порядок, а виклик перестає читатися. Виходять із цього по-різному: групують пов'язані дані в один список, розбивають функцію на дві або дають параметрам імена прямо при виклику — у Python можна писати `рамка(символ="*", ширина=20)`, і тоді порядок не має значення.

**Помилка, якої не видно.** Ситуація із завдання 5 у зошиті, коли переплутаний порядок аргументів не дає помилки, а мовчки працює, — одна з найнеприємніших. Помилка з'являється на екрані одразу й лягає в очі, а мовчазна може прожити в програмі роками. Саме тому в серйозних системах на початку функції перевіряють, чи справді прийшло те, що очікували.
