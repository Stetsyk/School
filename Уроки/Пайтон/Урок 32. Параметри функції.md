## 2. Пояснення (8-10 хв)

### Блок 1. Параметр

Параметр — це змінна, яку функція отримує ззовні. Пишеться в тих самих круглих дужках, які досі стояли порожні.

```
def рамка(ширина):
    print("=" * ширина)
```

Тепер при виклику ширину вказують у дужках:

```
рамка(30)
рамка(50)
рамка(10)
```

Одна функція, три різні результати.

Значення, яке передають при виклику, називають **аргументом**. Тобто `ширина` — це параметр в описі, а `30` — аргумент при виклику. Різниця в словах невелика, і на практиці їх часто плутають, нічого страшного.

> 📝 **Параметр** — змінна, яку функція отримує ззовні. Записується в дужках при описі.
>
> ```
> def рамка(ширина):
>     print("=" * ширина)
> ```
>
> **Аргумент** — конкретне значення, яке передають при виклику: `рамка(30)`.

> ❓ **Скільки різних рамок можна отримати від функції `рамка(ширина)`?**
>
> *Очікуємо:* скільки завгодно, залежно від переданого числа.

### Блок 2. Кілька параметрів

Параметрів може бути кілька — тоді їх перелічують через кому.

```
def рамка(символ, ширина):
    print(символ * ширина)

рамка("=", 30)
рамка("*", 50)
рамка("-", 10)
```

**Порядок має значення.** Перший аргумент потрапляє в перший параметр, другий у другий. Якщо переплутати місцями і написати `рамка(30, "=")`, Python спробує помножити число на текст у зворотному порядку і, залежно від дії, або видасть помилку, або зробить не те.

Кількість теж має збігатися: якщо параметрів два, а передали один — буде помилка `TypeError`.

> 📝 **Кілька параметрів** перелічують через кому: `def рамка(символ, ширина):`
> **Порядок аргументів має значення** — перший іде в перший параметр.
> Кількість аргументів має збігатися з кількістю параметрів.

> ❓ **Що станеться при виклику `рамка("=")`, якщо функція описана з двома параметрами?**
>
> *Очікуємо:* помилка, бракує другого аргументу.

### Блок 3. Параметр живе тільки всередині

Параметр — звичайна змінна, але існує вона **тільки в тілі функції**. Зовні її не видно.

```
def вітання(ім'я):
    print(f"Привіт, {ім'я}!")

вітання("Оля")
print(ім'я)        → NameError, такої змінної немає
```

Це не обмеження, а зручність. Завдяки цьому в різних функціях можна спокійно брати однакові імена параметрів і не боятися, що вони переплутаються.

І навпаки: те, що змінна називається так само зовні, нічого не означає — функція працює зі своєю копією.

```
ім'я = "Іван"

def вітання(ім'я):
    ім'я = "Оля"
    print(ім'я)

вітання("Марія")     → Оля
print(ім'я)          → Іван
```

> 📝 **Параметр існує тільки всередині функції.** Зовні його не видно, і зміни всередині не впливають на зовнішні змінні з таким самим іменем.

> ❓ **Чи можна звернутися до параметра після того, як функція відпрацювала?**
>
> *Очікуємо:* ні, він існує лише в тілі функції.

### Блок 4. Функція друкує, а не повертає

Поки що всі наші функції щось **виводять** на екран. Це важлива обмеженість, і її варто помітити зараз.

```
def площа(a, b):
    print(a * b)

площа(5, 4)              → 20 на екрані
```

Функція справді порахувала. Але результат одразу пішов на екран — і використати його далі не вийде:

```
всього = площа(5, 4) * 2      → не працює як очікується
```

Функція, яка друкує, годиться для оформлення: рамки, заголовки, меню, повідомлення. Для обчислень потрібно вміти **повертати** результат, а не друкувати — про це буде наступний урок.

> 📝 Функція, яка друкує результат, годиться для **оформлення**. Для обчислень результат треба **повертати** — це тема наступного уроку.

> ❓ **Чому результат функції, яка друкує, не можна використати в подальших обчисленнях?**
>
> *Очікуємо:* він пішов на екран, а не у програму, зберегти його ніде.

#### ✅ Відповіді до бонусів

**Бонус 1.**
```
def показати(список):
    for i in range(len(список)):
        print(f"{i + 1}. {список[i]}")

показати(["Київ", "Львів", "Одеса"])
```
Головна ідея: параметром може бути не лише число чи текст, а й цілий список.

**Бонус 2.** `[1, 2, 3, 100]`. Здавалося б, функція працює з копією, але зі списками це не так: у параметр потрапляє не копія списку, а те саме ім'я. Тому зміни всередині функції видно й зовні. Для чисел і рядків так не буває. Якщо змінювати список не треба, у функцію передають його копію: `додати(числа[:])`.

**Бонус 3.** `7` і `-7`. Значення потрапляють у параметри **за порядком**: перше число стає `a`, друге `b`. Тому переставлені аргументи дають інший результат, хоч виклик виглядає майже однаково. У Python є спосіб убезпечитися — називати аргументи явно: `різниця(b=3, a=10)` дасть 7 незалежно від порядку.

**Бонус 4.** Обидва дадуть помилку `TypeError`: Python вимагає **точно стільки** аргументів, скільки параметрів у описі. Щоб дозволити виклик з одним числом, параметру дають значення за замовчуванням: `def різниця(a, b=0):`. Тоді `різниця(10)` спрацює й дасть 10, а `різниця(10, 3)` — 7. Параметри зі значеннями за замовчуванням завжди ставлять **останніми** в описі.

## 7. Якщо лишився час

**Скільки параметрів забагато.** Загальна домовленість: більше чотирьох параметрів — привід задуматися. При п'яти й більше майже неможливо не переплутати порядок, а виклик перестає читатися. Виходять із цього по-різному: групують пов'язані дані в один список, розбивають функцію на дві або дають параметрам імена прямо при виклику — у Python можна писати `рамка(символ="*", ширина=20)`, і тоді порядок не має значення.

**Помилка, яка не видно.** Ситуація із завдання 1, коли переплутаний порядок аргументів не дає помилки, а мовчки працює, — одна з найнеприємніших. Помилка з'являється на екрані одразу й лягає в очі, а мовчазна може прожити в програмі роками. Саме тому в серйозних системах на початку функції перевіряють, чи справді прийшло те, що очікували.
