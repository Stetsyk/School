## 1. Вступ-гачок (2-3 хв)

Я загадав число від 1 до 100. У вас сім спроб. Починайте.

Хтось скаже «50». І це правильний перший хід — не тому, що пощастить, а тому що після нього залишиться рівно половина варіантів.

Скажу «більше». Тепер варіантів п'ятдесят. Наступний хід — 75, і залишиться двадцять п'ять. Потім тринадцять, сім, чотири, два, один.

Порахуйте: щоб знайти будь-яке число від 1 до 100, вистачає семи спроб. Завжди. Навіть якщо число найневдаліше.

Сьогодні ми напишемо цю гру. У ній зійдеться все, що ми вивчили за шість уроків про цикли: сам цикл, умова всередині, лічильник, вихід за подією. А заразом розберемось, чому саме сім.

## 2. Пояснення (6-8 хв)

### Блок 1. Алгоритм гри

Опишемо гру словами, перш ніж писати код.

1. Загадати число
2. Обнулити лічильник спроб
3. Повторювати: запитати варіант → збільшити лічильник → якщо вгадав, вийти → інакше підказати «більше» чи «менше»
4. Вивести результат і кількість спроб

Найважливіше питання: який цикл узяти? Кількість спроб наперед невідома, вона залежить від гравця. Отже, `while`.

> 📝 **Алгоритм гри:** загадати → обнулити лічильник → повторювати запит із підказками, поки не вгадано → вивести кількість спроб.
> Кількість спроб невідома наперед, тому потрібен цикл `while`.

> ❓ **Чому для цієї гри не підходить цикл `for`?**
>
> *Очікуємо:* невідомо наперед, скільки спроб знадобиться гравцеві.

### Блок 2. Основа програми

```
загадане = 42
спроб = 0

while True:
    варіант = int(input("Ваш варіант: "))
    спроб += 1
    if варіант == загадане:
        print(f"Вгадали за {спроб} спроб!")
        break
    elif варіант < загадане:
        print("Більше")
    else:
        print("Менше")
```

Тут працює прийом із уроку 21: `while True` крутить цикл нескінченно, а `break` виходить із нього, коли гравець вгадав.

Зверніть увагу на порядок гілок: спершу перевіряємо збіг, і лише потім — у який бік помилка. Якби першою стояла перевірка «менше», гілка з перемогою просто ніколи б не спрацювала.

> 📝 **Основа гри:** `while True` крутить цикл, `break` виходить при вгадуванні.
> Спершу перевіряють збіг, потім напрямок помилки.

> ❓ **Що станеться, якщо в цій програмі прибрати `break`?**
>
> *Очікуємо:* гра не закінчиться навіть після правильної відповіді, цикл крутитиметься далі.

### Блок 3. Обмеження спроб

Щоб гра стала складнішою, обмежимо кількість спроб. Тоді умова циклу перестає бути `True` і стає осмисленою:

```
while спроб < 7:
    ...
```

Але тут з'являється тонкість: після виходу з циклу треба зрозуміти, чому саме він закінчився — гравець вгадав чи спроби скінчилися. Для цього заводять прапорець:

```
вгадав = False
while спроб < 7 and not вгадав:
    ...
    if варіант == загадане:
        вгадав = True
```

Після циклу перевіряємо прапорець і виводимо потрібне повідомлення.

> 📝 **Прапорець** — змінна `True` або `False`, яка запам'ятовує, чи сталася подія. Після циклу її перевіряють, щоб зрозуміти, чим цикл закінчився.

> ❓ **Навіщо потрібен прапорець, якщо є `break`?**
>
> *Очікуємо:* щоб після виходу з циклу знати, чи гравець вгадав, чи просто вичерпав спроби.

## 3. Перевірка розуміння (3-5 хв)

1. **Який цикл потрібен для гри й чому?**
   `while`, бо кількість спроб наперед невідома.

2. **Що робить `break` у цій програмі?**
   Виходить із циклу, коли гравець вгадав.

3. **Чому перевірку на збіг ставлять першою?**
   Інакше спрацює одна з гілок про напрямок, і виграшу програма не помітить.

4. **Що таке прапорець?**
   Змінна `True` або `False`, яка запам'ятовує, чи сталася подія.

5. **Скільки спроб треба, щоб гарантовано вгадати число від 1 до 100?**
   Сім, якщо щоразу ділити діапазон навпіл.

Підказка: перевірку меж робіть до збільшення лічильника, а після попередження використайте `continue` — команду, яка пропускає решту тіла циклу й іде на наступний крок.

**Завдання 3. Проєкт «Вгадай число».**
Четвертий проєкт курсу, оцінюється. Доведіть гру до готового вигляду.

Обов'язкові умови:
1. привітання з правилами гри на початку
2. цикл із підказками «більше» та «менше»
3. лічильник спроб
4. обмеження в сім спроб і прапорець для розрізнення виграшу й програшу
5. перевірка меж введеного числа без витрати спроби
6. фінальне повідомлення: скільки спроб витрачено, а в разі програшу — яке було число
7. оцінка гри словами: за 1-3 спроби «блискуче», за 4-5 «добре», за 6-7 «ледве встигли»

Загадане число поки що задає програміст у коді. Наступного тижня, на уроці 35, ми зробимо його справді випадковим — тоді в гру можна буде грати самому.

Готову гру дайте зіграти сусідові по парті й запишіть у зошит, за скільки спроб він упорався.

## 5. ⭐ Бонус для сильних

**Бонус 1.** Поміняйтеся ролями: тепер число загадує гравець, а вгадує програма. Напишіть її так, щоб вона вгадувала за стратегією поділу навпіл, а гравець відповідав `б` (більше), `м` (менше) або `в` (вгадав).

**Бонус 2.** Скільки спроб потрібно для діапазону від 1 до 1000? А від 1 до мільйона?

**Бонус 3.** Комп'ютер загадав число від 1 до 100. Яка стратегія гарантує перемогу найшвидше і за скільки спроб у найгіршому випадку?

**Бонус 4.** Поміняйтеся ролями: тепер **комп'ютер** відгадує задумане вами число, а ви відповідаєте «більше», «менше» або «вгадав». Опишіть алгоритм програми.

#### ✅ Відповіді до бонусів

**Бонус 1.**
```
низ = 1
верх = 100
спроб = 0
while True:
    варіант = (низ + верх) // 2
    спроб += 1
    print("Моя здогадка:", варіант)
    відповідь = input("б / м / в: ")
    if відповідь == "в":
        print(f"Вгадав за {спроб} спроб")
        break
    elif відповідь == "б":
        низ = варіант + 1
    else:
        верх = варіант - 1
```
Головна ідея: після кожної підказки звужується не список варіантів, а межі діапазону.

**Бонус 2.** 10 і 20. Кожна спроба ділить діапазон навпіл, тому кількість спроб — це степінь двійки, найближчий згори: 2 у десятому степені це 1024, 2 у двадцятому — понад мільйон. Тобто діапазон збільшився в тисячу разів, а спроб знадобилося лише вдвічі більше.

**Бонус 3.** Називати щоразу **середину** проміжку, що лишився: спершу 50, потім 25 або 75 і так далі. Кожна спроба зменшує кількість варіантів удвічі: 100 → 50 → 25 → 13 → 7 → 4 → 2 → 1, тобто **сім** спроб у найгіршому випадку. Спосіб називають двійковим пошуком, і саме ним ваш телефон знаходить контакт серед тисяч записів.

**Бонус 4.** Програма тримає дві межі й називає середину.
```
низ = 1
верх = 100
while True:
    спроба = (низ + верх) // 2
    print("Це", спроба, "?")
    відповідь = input("більше / менше / вгадав: ")
    if відповідь == "вгадав":
        break
    elif відповідь == "більше":
        низ = спроба + 1
    else:
        верх = спроба - 1
```
Головна деталь — `+ 1` і `− 1` при зсуві меж: без них програма може назвати те саме число вдруге й зациклитися.
