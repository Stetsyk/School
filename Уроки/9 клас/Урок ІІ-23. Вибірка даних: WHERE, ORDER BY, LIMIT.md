## 1. Вступ-гачок (2-3 хв)

Уявіть, що ви прийшли в бібліотеку й кажете бібліотекарці: «Дайте мені всі книжки».

Приблизно це робить запит `SELECT * FROM books;`. У навчальній базі він поверне дванадцять рядків, і це ще нічого. У справжній базі шкільної бібліотеки їх буде десять тисяч, а в базі магазину — мільйон.

Такий запит теж пишеться одним рядком, і сьогодні ви навчитеся його складати. Це найважливіше вміння всієї теми: **вибирати саме те, що потрібно**, а не все підряд.

## 2. Пояснення (8-10 хв)

### Блок 1. WHERE — умова відбору

`WHERE` ставиться після `FROM` і залишає тільки ті записи, для яких умова істинна.

```sql
SELECT title, year FROM books WHERE year > 2000;
```

Оператори порівняння знайомі, окрім одного.

| Оператор | Означає |
| --- | --- |
| `=` | дорівнює |
| `<>` | не дорівнює |
| `>` `<` | більше, менше |
| `>=` `<=` | не менше, не більше |

У SQL рівність — це **один** знак `=`, а не два, як у Python. Нерівність — `<>`, як в електронних таблицях.

Текст у порівнянні беруть **в одинарні лапки**, числа — ні.

```sql
SELECT * FROM books WHERE genre = 'Проза';
SELECT * FROM books WHERE pages < 200;
```

> 📝 **`WHERE умова`** лишає тільки записи, для яких умова істинна.
> `=` дорівнює · `<>` не дорівнює · `>` `<` `>=` `<=`.
> Текст у порівнянні — **в одинарних лапках**, числа без лапок.

> ❓ **Чим `WHERE genre = 'Проза'` відрізняється від `WHERE genre = Проза`?**
>
> *Очікуємо:* без лапок база шукатиме поле з іменем `Проза` й видасть помилку.

### Блок 2. Кілька умов

Умови сполучають словами `AND`, `OR`, `NOT`. Це ті самі логічні операції, які ви знаєте з Python і з електронних таблиць.

```sql
SELECT * FROM books WHERE genre = 'Проза' AND year > 2000;
SELECT * FROM books WHERE genre = 'Поезія' OR genre = 'Драма';
SELECT * FROM books WHERE NOT genre = 'Проза';
```

Коли `AND` і `OR` стоять разом, **обов'язкові дужки**. Без них база спершу виконає `AND`, і результат буде не той, який ви мали на увазі.

```sql
SELECT * FROM books WHERE (genre = 'Поезія' OR genre = 'Драма') AND year < 1950;
```

Два скорочення, які роблять запит коротшим і зрозумілішим.

**`BETWEEN a AND b`** — значення в межах, разом із самими межами.
**`IN (список)`** — значення входить у перелік.

```sql
SELECT * FROM books WHERE year BETWEEN 1900 AND 1950;
SELECT * FROM books WHERE genre IN ('Поезія','Драма','Казка');
```

> 📝 **`AND`** обидві умови · **`OR`** хоч одна · **`NOT`** заперечення.
> Коли `AND` і `OR` разом — **обов'язкові дужки**.
> **`BETWEEN a AND b`** діапазон разом із межами · **`IN (…)`** входить у перелік.

> ❓ **Як коротше записати `genre = 'Поезія' OR genre = 'Драма' OR genre = 'Казка'`?**
>
> *Очікуємо:* `genre IN ('Поезія','Драма','Казка')`.

### Блок 3. Пошук за частиною тексту

Коли точного значення ви не знаєте, використовують `LIKE` із **шаблоном**. У шаблоні працюють два спецсимволи.

**`%`** — будь-яка кількість будь-яких символів, зокрема жодного.
**`_`** — рівно один будь-який символ.

```sql
SELECT * FROM books WHERE title LIKE 'Т%';        назва починається на Т
SELECT * FROM books WHERE author LIKE '%Дж.%';    автор містить Дж.
SELECT * FROM books WHERE title LIKE '%принц%';   назва містить слово принц
SELECT * FROM books WHERE genre LIKE 'Каз_а';     Казка, Казна тощо
```

Це саме той пошук, який працює в полі «пошук по сайту»: користувач вводить шматок слова, а система підставляє його між двома відсотками.

Окремо — пошук порожніх значень. `NULL` не дорівнює нічому, навіть самому собі, тому `WHERE genre = NULL` **ніколи** нічого не поверне. Для цього є окремі слова.

```sql
SELECT * FROM books WHERE genre IS NULL;
SELECT * FROM books WHERE genre IS NOT NULL;
```

> 📝 **`LIKE 'шаблон'`** — пошук за частиною тексту. `%` будь-які символи · `_` рівно один символ.
> `'Т%'` починається на Т · `'%принц%'` містить слово · `'%ко'` закінчується на ко.
> **`IS NULL`** і **`IS NOT NULL`** — перевірка на порожнє значення. `= NULL` не працює ніколи.

> ❓ **Який шаблон знайде всіх авторів, чиє прізвище закінчується на `ко`?**
>
> *Очікуємо:* `LIKE '%ко%'` не годиться, потрібне `LIKE '%ко %'` або точніше за структурою поля. Для прізвища перед ініціалом підійде `'%ко %'`.

### Блок 4. Порядок і кількість

**`ORDER BY поле`** упорядковує результат. `ASC` за зростанням, це за замовчуванням, `DESC` за спаданням.

```sql
SELECT title, year FROM books ORDER BY year DESC;
```

Полів може бути кілька. Тоді друге впорядковує всередині груп із однаковим першим — точно як багаторівневе сортування в електронних таблицях.

```sql
SELECT * FROM books ORDER BY genre ASC, year DESC;
```

**`LIMIT n`** повертає тільки перші `n` рядків. Разом із сортуванням це дає відповідь на питання «топ-3» або «найдовша книжка».

```sql
SELECT title, pages FROM books ORDER BY pages DESC LIMIT 3;
```

**`DISTINCT`** прибирає повтори з результату.

```sql
SELECT DISTINCT genre FROM books;
```

І найважливіше на цьому уроці — **порядок частин запиту**. Він жорсткий, переставляти не можна.

```sql
SELECT поля FROM таблиця WHERE умова ORDER BY поле LIMIT n;
```

> 📝 **Порядок частин запиту, змінювати не можна:**
>
> ```sql
> SELECT поля
> FROM таблиця
> WHERE умова
> ORDER BY поле DESC
> LIMIT n;
> ```
>
> `ORDER BY` сортує · `DESC` за спаданням · `LIMIT n` перші n рядків · `DISTINCT` без повторів.

> ❓ **Як вивести три найтовщі книжки?**
>
> *Очікуємо:* `SELECT title, pages FROM books ORDER BY pages DESC LIMIT 3;`

## 5. ⭐ Бонус для сильних

**Бонус 1.** Запит `SELECT title FROM books ORDER BY pages DESC LIMIT 1;` знаходить найтовщу книжку. Придумайте, як знайти **другу** за товщиною, і поясніть свій спосіб.
*Правильна відповідь:* потрібне слово `OFFSET`, яке пропускає задану кількість рядків: `SELECT title FROM books ORDER BY pages DESC LIMIT 1 OFFSET 1;`. Спершу база сортує, потім пропускає один рядок і бере наступний. Саме цим механізмом працює гортання сторінок у будь-якому інтернет-магазині: друга сторінка результатів — це `LIMIT 20 OFFSET 20`, третя — `OFFSET 40`. Зараховуємо й відповідь через `LIMIT 2` з подальшим переглядом другого рядка, але з поясненням, чим `OFFSET` точніший.

**Бонус 2.** Умова `WHERE year > 1900 AND year < 2000` і умова `WHERE year BETWEEN 1900 AND 2000` дають різні результати. Поясніть різницю й скажіть, у якому випадку це справді важливо.
*Правильна відповідь:* `BETWEEN` включає **обидві межі**, а знаки `>` і `<` — ні. Тобто перший запит не покаже книжку 1900 року й книжку 2000 року, а другий покаже. Важливо це майже завжди, коли йдеться про дати й гроші: запит «замовлення за березень» із межами `> 01.03` і `< 31.03` тихо загубить перше й останнє число місяця. Помилку такого роду називають помилкою на одиницю, і вона одна з найпоширеніших у програмуванні взагалі.

Порядок дій: візьміть свою таблицю «Моя бібліотека», яку ви спроєктували на першому уроці теми й описали командою `CREATE TABLE` на другому. Тепер напишіть до неї **три запити**. Перший — з умовою `WHERE`: щось відібрати, наприклад книжки після певного року або товщі за певну кількість сторінок. Другий — із сортуванням `ORDER BY`: вивести всі записи впорядкованими, обов'язково вкажіть напрямок. Третій — з обома частинами разом і ще з `LIMIT`: відібрати за умовою, упорядкувати й показати перші три. Для кожного запиту запишіть у зошит три речі: сам запит, **словесне формулювання** питання, на яке він відповідає, і скільки рядків він поверне на ваших даних. Стежте за порядком частин: `SELECT`, `FROM`, `WHERE`, `ORDER BY`, `LIMIT`.

**Якщо є комп'ютер:** виконайте всі три запити на `sqliteonline.com` і перевірте, чи збігається кількість рядків із тією, яку ви передбачили. Якщо не збіглася, випишіть, чому.

## 7. Якщо лишився час

**Чому пошук працює миттєво.** Запит із `WHERE` до таблиці на мільйон записів виконується за частки секунди, хоча база начебто мусила б переглянути всі мільйон рядків. Насправді вона їх не переглядає: для полів, за якими часто шукають, будують **індекс** — окрему службову структуру, схожу на алфавітний покажчик у кінці підручника. Пошук по індексу займає приблизно двадцять кроків замість мільйона. Платою є місце на диску й трохи повільніше додавання нових записів, бо індекс теж треба оновлювати. Тому індекси створюють свідомо, а не на всі поля підряд.

**Найдорожчий пропущений `WHERE`.** У 2012 році фінансова компанія Knight Capital випустила оновлення програми, у якому один старий шматок коду почав спрацьовувати там, де не мав. Програма за 45 хвилин наробила помилкових операцій на біржі на суму близько 440 мільйонів доларів. Компанія, яка існувала сімнадцять років, збанкрутувала за один робочий ранок. Формально причина була складніша за забутий `WHERE`, але суть та сама: команда, виконана не на тих даних, на яких малося на увазі. Саме тому професійне правило «спершу `SELECT`, потім усе решта» звучить нудно рівно доти, доки не спрацює вперше.
