## 1. Вступ-гачок (2-3 хв)

Найвідоміша помилка в історії роботи з базами даних виглядає так:

```sql
UPDATE books SET copies = 0;
```

Виглядає безневинно. Насправді цей рядок щойно обнулив кількість примірників **усіх** книжок у бібліотеці. Не однієї. Усіх.

Автор хотів написати ось так:

```sql
UPDATE books SET copies = 0 WHERE id = 7;
```

Забув чотири символи наприкінці. Скасувати не можна: `Ctrl + Z` у базі даних не існує.

Це трапляється в справжніх компаніях кілька разів на рік і завжди потрапляє в новини. Сьогодні ви навчитеся чотирьох команд, які створюють, наповнюють, змінюють і видаляють дані, — і одного правила, яке рятує від цієї помилки назавжди.

## 2. Пояснення (8-10 хв)

### Блок 1. CREATE TABLE — створюємо таблицю

Таблицю в базі не малюють мишкою, її **описують командою**.

```sql
CREATE TABLE readers (
  id        INTEGER PRIMARY KEY,
  surname   TEXT    NOT NULL,
  name      TEXT    NOT NULL,
  class     TEXT,
  join_date DATE,
  has_debt  INTEGER DEFAULT 0
);
```

Розберемо по частинах.

**`CREATE TABLE ім'я (` … `);`** — оболонка команди.
**Кожен рядок усередині** — це одне поле: спершу ім'я, потім тип.
**`PRIMARY KEY`** — позначає первинний ключ. У SQLite поле `INTEGER PRIMARY KEY` заповнюється **само**: якщо не вказати значення, база поставить наступний вільний номер.
**`NOT NULL`** — поле не можна лишити порожнім.
**`DEFAULT значення`** — що поставити, якщо при додаванні запису поле не вказали.

Кома стоїть після кожного поля, крім останнього. Це найчастіша синтаксична помилка на цьому уроці.

> 📝 **Створення таблиці**
>
> ```sql
> CREATE TABLE ім'я (
>   поле  ТИП  обмеження,
>   поле  ТИП  обмеження
> );
> ```
>
> `PRIMARY KEY` первинний ключ · `NOT NULL` не можна порожнім · `DEFAULT x` значення за замовчуванням.
> Кома після кожного поля, крім останнього.

> ❓ **Що станеться, якщо додати читача без прізвища в таблицю з `surname TEXT NOT NULL`?**
>
> *Очікуємо:* база відмовить і запис не додасться.

### Блок 2. INSERT — додаємо записи

Два способи, і другий кращий.

**Повний** — перелічуємо значення всіх полів по порядку.

```sql
INSERT INTO readers VALUES (1,'Коваль','Олена','9-Б','2026-09-02',0);
```

**З переліком полів** — вказуємо, у які саме поля кладемо значення.

```sql
INSERT INTO readers (surname, name, class)
VALUES ('Ткаченко','Юрій','9-А');
```

Другий спосіб кращий одразу з трьох причин: не треба пам'ятати порядок полів, можна пропустити необов'язкові, і запит не зламається, якщо в таблицю колись додадуть нове поле.

Кілька записів додають одним запитом через кому:

```sql
INSERT INTO readers (surname, name, class) VALUES
 ('Бондар','Олег','9-Б'),
 ('Лисенко','Тарас','9-А'),
 ('Марчук','Анна','9-В');
```

І про лапки. **Текст і дати — в одинарних лапках.** Числа — без лапок. Якщо всередині тексту є апостроф, його подвоюють: `'Мар''яна'`.

> 📝 **Додавання записів**
>
> ```sql
> INSERT INTO таблиця (поле1, поле2) VALUES ('текст', 42);
> ```
>
> Перелік полів кращий за повний запис.
> Текст і дати **в одинарних лапках**, числа без лапок. Апостроф усередині подвоюється.

> ❓ **Чому `INSERT` із переліком полів надійніший за повний?**
>
> *Очікуємо:* він не залежить від порядку полів і не зламається, коли в таблицю додадуть нове поле.

### Блок 3. UPDATE — змінюємо наявні дані

```sql
UPDATE readers SET class = '10-Б' WHERE id = 1;
```

Три частини: **що** змінюємо (`UPDATE таблиця`), **на що** (`SET поле = значення`), **де саме** (`WHERE умова`).

Полів у `SET` може бути кілька через кому:

```sql
UPDATE books SET copies = 6, genre = 'Класика' WHERE id = 3;
```

Значення можна рахувати з поточного:

```sql
UPDATE books SET copies = copies - 1 WHERE id = 9;
```

І тепер найголовніше речення уроку.

**`UPDATE` без `WHERE` змінює всі записи таблиці.**

Це не помилка синтаксису, база виконає команду мовчки й повідомить, що змінено 12 рядків. Тому існує правило, якого дотримуються професіонали без винятків.

**Спершу напишіть `SELECT` із тим самим `WHERE`.** Подивіться, які рядки він показав. Якщо саме ті — замініть `SELECT *` на `UPDATE … SET …` і виконуйте.

> 📝 **Зміна записів**
>
> ```sql
> UPDATE таблиця SET поле = значення WHERE умова;
> ```
>
> **`UPDATE` без `WHERE` змінює всю таблицю.**
> Правило: спершу той самий запит як `SELECT`, подивитися рядки, і лише потім `UPDATE`.

> ❓ **Що зробить `UPDATE books SET year = 2020;`?**
>
> *Очікуємо:* поставить 2020 роком видання **всім** книжкам у таблиці.

### Блок 4. DELETE — вилучаємо записи

```sql
DELETE FROM readers WHERE id = 5;
```

Та сама будова й та сама пастка, тільки наслідки гірші.

**`DELETE FROM таблиця;` без `WHERE` видаляє всі записи.** Таблиця лишиться, але порожня.

Ще дві команди, які варто розрізняти.

**`DROP TABLE ім'я;`** — видаляє таблицю **разом зі структурою**. Після цього немає ні даних, ні самої таблиці.
**`ALTER TABLE ім'я ADD COLUMN поле ТИП;`** — додає нове поле до наявної таблиці, дані при цьому зберігаються.

І важлива відмінність від усього, з чим ви працювали раніше. В електронній таблиці є `Ctrl + Z`. У базі даних його **немає**: команда виконана — значить, виконана. Захист від помилок тут один — **резервна копія** і звичка перевіряти `WHERE` через `SELECT`.

> 📝 **Вилучення**
>
> ```sql
> DELETE FROM таблиця WHERE умова;
> ```
>
> Без `WHERE` видаляються **всі** записи. `DROP TABLE` видаляє й саму таблицю.
> `ALTER TABLE … ADD COLUMN` додає поле, дані зберігаються.
> **У базі даних немає `Ctrl + Z`.** Рятує резервна копія й перевірка через `SELECT`.

> ❓ **Чим `DELETE FROM books;` відрізняється від `DROP TABLE books;`?**
>
> *Очікуємо:* після першої таблиця лишається порожньою, після другої таблиці немає взагалі.

## 3. Перевірка розуміння (3-5 хв)

1. **Що робить `NOT NULL` у створенні таблиці?**
   Забороняє лишати це поле порожнім.

2. **Чому `INSERT` краще писати з переліком полів?**
   Не залежить від порядку полів і не ламається, коли додають нове поле.

3. **Що станеться з `UPDATE` без `WHERE`?**
   Зміняться всі записи таблиці.

4. **Яке правило захищає від цієї помилки?**
   Спершу виконати той самий запит як `SELECT` і подивитися рядки.

5. **Чим `DELETE` відрізняється від `DROP TABLE`?**
   `DELETE` прибирає записи, `DROP TABLE` — усю таблицю зі структурою.

## 5. ⭐ Бонус для сильних

**Бонус 1.** У SQLite поле `INTEGER PRIMARY KEY` заповнюється само. Що станеться з нумерацією, якщо додати п'ять записів, потім видалити третій і додати шостий? Який номер отримає новий запис і чому це важливо розуміти?
*Правильна відповідь:* новий запис отримає номер **6**, а не 3. База бере максимальний наявний номер і додає одиницю, вона не переиспользує звільнені номери. Розуміти це важливо з двох причин. По-перше, номери в таблиці не обов'язково йдуть підряд, і рахувати записи за найбільшим `id` не можна — для цього є `COUNT`. По-друге, це правильна поведінка: якщо номер 3 уже згадувався десь в іншій таблиці, повторне використання зв'язало б старі записи з новою книжкою.

**Бонус 2.** Придумайте, як зробити `UPDATE`, який можна скасувати, маючи тільки команди цього уроку.
*Правильна відповідь:* зробити копію таблиці перед зміною. У SQL це один запит: `CREATE TABLE books_backup AS SELECT * FROM books;`. Після нього в базі лежить повна копія, і якщо `UPDATE` пішов не так, дані відновлюють із неї. Саме так і працюють професіонали: перед будь-якою масовою зміною роблять копію, а після перевірки видаляють її. Це найпростіша форма того, що у великих системах називають резервним копіюванням і транзакціями.

## 6. Домашнє завдання

**§ 6.1.** Напишіть команду `CREATE TABLE` для своєї таблиці «Моя бібліотека» і три команди `INSERT` до неї.

Порядок дій: візьміть проєкт таблиці, який ви зробили минулого уроку в зошиті. Тепер запишіть його справжньою командою `CREATE TABLE`: кожне поле окремим рядком, спершу ім'я, потім тип, далі обмеження. Обов'язково має бути `PRIMARY KEY` і щонайменше два поля з `NOT NULL`. Одному полю задайте `DEFAULT`. Не забудьте про коми після кожного поля, крім останнього, і крапку з комою в кінці. Далі напишіть **три команди `INSERT`** із трьома реальними книжками. Перша команда — повна, з переліком усіх значень. Друга — з переліком полів. Третя — така, що додає **одразу два записи** одним запитом. Усе запишіть у зошит.

**Якщо є комп'ютер:** виконайте свої команди на `sqliteonline.com`, перевірте результат запитом `SELECT * FROM` і допишіть у зошит, скільки рядків повернулося. Якщо база видала помилку, випишіть її текст і те, як ви її виправили — це цінніше за роботу, яка запрацювала з першого разу.

## 7. Якщо лишився час

**Ніч, коли зникла база.** У 2017 році один розробник великої платформи виконував рутинне обслуговування о пів на дванадцяту ночі. Він набрав команду видалення каталогу на резервному сервері, помилився вікном терміналу й виконав її на основному. За кілька секунд зникло понад 300 гігабайтів робочих даних. Далі з'ясувалося найцікавіше: у компанії було п'ять різних механізмів резервного копіювання, і жоден із них насправді не працював — їх ніхто ніколи не перевіряв відновленням. Дані врятувала випадкова копія, зроблена шість годин тому для іншої задачі. Звідси головне правило галузі: резервна копія, з якої жодного разу не відновлювали, — це не резервна копія.

**Чому база не питає «ви впевнені».** Коли ви видаляєте файл, система перепитує. Коли ви виконуєте `DELETE FROM`, база мовчки видаляє. Це не недогляд, а свідоме рішення: СКБД розрахована на те, що запити їй надсилає **програма**, а не людина, і мільйон запитів за секунду не можна супроводжувати питаннями. Захист переклали на інші механізми — права доступу, за яких звичайний користувач узагалі не має дозволу на видалення, транзакції, які можна відкотити, і резервні копії. Тому пряме підключення до робочої бази вручну у великих компаніях вважають надзвичайною подією й вимагають, щоб поруч сидів другий інженер.
